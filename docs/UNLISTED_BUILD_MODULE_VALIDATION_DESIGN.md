# 未登记游戏构建的模块下载与本地安全验证设计

状态：三轮设计审查与三轮实现复核均已通过，允许提交和发布。

## 问题与目标

当前模块目录把“可以下载模块”和“已经确认支持当前游戏构建”合并成了同一个判断。目录中没有精确命中 EXE、`GameAssembly.dll` 与 `global-metadata.dat` 三项指纹时，主程序会在下载前返回不可用，因此模块自己的只读语义结构校验永远没有机会运行。

本设计把两件事拆开：

- 下载资格由模块身份、主程序版本、Host API、包地址、大小和 SHA-256 决定。
- 运行资格优先由目录中的精确构建指纹决定；未精确登记时，只允许明确声明具备安全验证能力的模块在本地执行只读检查。

下载、安装或版本号更高都不等于兼容。任何未通过精确指纹或本地语义校验的模块都不得创建页面、读取业务数据或执行写入。

## 显式能力声明

模块清单和目录版本快照新增可选布尔字段：

```json
"supportsUnlistedBuildValidation": true
```

- 缺失或 `false`：仍按原规则处理，目录没有精确构建记录时不提供下载、更新或回退。
- `true`：目录没有任何精确候选时，可以提供该模块 ID 的最新主程序兼容版本作为“下载后验证”候选。
- 该能力只表示模块的 `Supports` 与兼容性诊断可以对未知构建安全失败，不表示未知构建已经兼容。
- 目录记录与包内 `module.json` 必须一致，防止目录误把普通模块声明为可探测模块。
- 这是 Schema 5 的向后兼容可选扩展；旧主程序忽略未知字段并继续只接受精确构建，新主程序将缺失字段视为 `false`，不提升目录 Schema，避免旧版主程序失去整个模块目录。

官方模块只有在以下条件全部满足后才能声明该能力：

1. `Supports` 不依赖目录中的固定指纹直接放行。
2. `Supports` 对进程、运行模式以及模块所需全部 IL2CPP 类型、字段和方法进行只读语义校验。
3. 任一成员缺失、类型异常、地址异常或运行模式不符合要求时安全返回 `false`。
4. Host API 5 以上模块提供只读 `IGameCompatibilityDiagnosticsProvider` 结果。
5. 有自动测试证明未知指纹能进入候选流程，同时未声明该能力的模块仍被拒绝。

## 候选选择

主程序先按进程名、当前主程序版本范围和 Host API 得到候选，再按以下顺序选择：

1. 如果存在精确构建候选，只在这些候选中选择最高版本，并按原规则计算更新和手动回退目标。
2. 如果不存在精确候选，只在 `supportsUnlistedBuildValidation=true` 的候选中选择最高版本。
3. 未登记构建的候选只允许下载或更新到最新版本，不提供未经精确确认的模块回退目标。
4. 如果没有精确候选，也没有显式安全验证候选，则保持不可用。

这样可以保证已经验证的旧构建不会被一个仅仅“版本较新”的未验证模块替代，也不会把旧模块版本猜测为安全回退包。

## 安装与启用状态

安装仍沿用现有安全链路：HTTPS、预期文件名、字节数、SHA-256、ZIP 路径穿越防护、包内清单一致性和版本隔离目录全部通过后，才更新 `installed.json`。

- 精确构建：安装后按现有流程加载。
- 未登记构建且游戏未连接：允许安装，状态显示“已安装，等待连接后验证”，不得声称兼容。
- 未登记构建、游戏已连接且属于首次安装：加载模块后立即调用 `Supports`。通过才绑定适配器并创建页面；失败则保留已校验的安装包，但模块不启用，并明确提示查看兼容性诊断或卸载。
- 替换已经加载的 Host API 6 以上模块：保持现有生命周期边界，安装后停用目标模块并要求手动重启；不得在当前进程加载新版本。重启并重新连接游戏后才执行 `Supports`，通过后启用，失败则继续停用。
- 后续每次连接仍重新执行 `Supports`，不把某次 PID、地址或会话结果持久化为构建兼容关系。
- 安装失败不改变原安装登记；模块更新仍遵守 Host API 6 以上替换后等待手动重启的规则。

## 诊断报告

报告必须区分四类结论：

- 目录精确支持：三个声明指纹组合命中同一构建记录。
- 可下载、待本地验证：没有精确记录，但模块显式支持未知构建校验。
- 本地验证通过：连接的模块对当前进程完成只读语义结构检查并接受。
- 本地验证失败：模块拒绝当前进程或结构，页面保持禁用。

当目录模块已识别时，报告逐项显示 EXE、GameAssembly 与 metadata 是否命中目录中的已登记值；未命中时同时显示当前哈希前缀、目录值前缀以及记录数量。`NotAvailable` 必须显示为失败而不是普通信息。报告仍不得包含本机路径、用户名、PID、内存地址或存档内容。

## 验证矩阵

### 目录选择

- 精确构建优先于所有未知构建候选。
- 未精确命中且能力为 `true` 时提供最新版本并标记待验证。
- 能力缺失或为 `false` 时保持不可用。
- 未登记构建不产生模块回退目标。
- 主程序版本或 Host API 不兼容时，即使能力为 `true` 也不得下载。

### 包与运行

- 目录和包内能力声明不一致时拒绝安装。
- 未连接游戏时安装后保持待验证。
- 已连接且 `Supports=true` 时启用页面。
- 已连接且 `Supports=false` 或抛出异常时安全停用，不执行写入。
- 精确构建的安装、更新和回退行为保持不变。

### 诊断与隐私

- 三项指纹分别显示匹配结果；Last Epoch 当前构建应显示 EXE 命中、GameAssembly 与 metadata 未命中旧目录记录。
- 可下载待验证使用提醒状态；完全没有可用候选使用失败状态。
- 本地语义验证结果和目录精确匹配结果不得混为一项。
- 脱敏测试继续拒绝路径、用户名、PID、地址和存档内容。

## 三轮设计审查记录

1. 方向审查：通过。下载资格与运行资格必须分离，但未知构建回退不能成为所有模块的默认行为，因此增加 `supportsUnlistedBuildValidation` 显式能力；精确构建仍具有最高优先级，能力缺失时继续安全拒绝。
2. 兼容与生命周期审查：通过并补正。Schema 5 采用旧主程序可忽略的可选布尔扩展，不切断 v0.4.4 的目录访问；首次安装可在当前进程验证，Host API 6 以上模块替换后必须停用并在手动重启后验证；未知构建不提供猜测回退。
3. 发布与可验证性审查：通过。两个仓库 `main` 与 `origin/main` 均为 0/0 同步；主程序最新正式标签为 `v0.4.4`，唯一下一版为 `v0.4.5`；Last Epoch 最新正式标签为 `last-epoch-v0.5.2`，唯一下一版为 `last-epoch-v0.5.3`。两组当前各保留 3 个可下载 Release，本次公开资产和元数据全部验证后会各删除最旧的第 4 个 Release、保留标签。新增 Last Epoch 实机测试只调用 `Supports` 与只读诊断，确认 `--offline` 主进程的完整语义结构后才允许登记新指纹。
