# 模块标记与固定操作栏布局设计

日期：2026-10-06。范围：宿主显示布局与必要的命令状态绑定；先方案、三轮设计检查、实现、三轮实现检查和文档同步，完成后提交发布。用户随后明确授权直接提交和发布，因此采用仅宿主运行时发布路径，下一版 0.4.8；模块不改动、不升版，不能覆盖已发布资产。

## 1. 确定的界面契约

- 游戏库条目的“已装专属模块”文字换成用户提供的插头图标，约 20×16 DIP，垂直居中，距离版本/字段摘要 16 DIP（用户在初版渲染后要求稍向右移，较初版增加 8 DIP）。提示及无障碍名称仍为“已装专属模块”；只表示已安装，不新增“构建兼容/已加载”的含义。
- “本游专属”按钮固定顺序：回退、查新、更新（未安装时为下载）、卸载、诊断、献者。按钮宽 64 DIP、高 32 DIP，相邻按钮实际边缘间距统一 8 DIP。无可用操作时置灰，不折叠；目标版本及后验证提示放 ToolTip，原手动回退确认仍明确目标版本。
- 右下角固定顺序：回退、查新、更新、官网。按钮宽 52 DIP、最低高 24 DIP，相邻按钮实际边缘间距统一 8 DIP。四个按钮始终可见，不能更新时更新置灰。
- 两排按钮都保持位置及宽度稳定，版本、检查中、下载进度、失败及待重启状态不能改按钮文字或增减按钮。状态文案和版本号不占按钮单元格。
- 模块按钮“查新”“更新”“诊断”“献者”及空页面提示同步缩写；不把未安装的下载命令误改成更新命令，不移除未知构建下载后的验证。

## 2. 图标资源与主题

原文件 E:/download/本机默认下载/chrome/GameValueEditorDedicatedModuleLoaded.png 以原始字节复制到宿主 Assets 并嵌入 WPF Resource，不依赖用户下载路径，不修改原图。PNG 为 1254×1254，透明留白较大；渲染层使用图片实际图形区域的相对 Viewbox，避免 20 DIP 图标内有效轮廓只有几像素。

以 ImageBrush 的 Alpha 作为 OpacityMask，Rectangle 使用 DynamicResource AccentBrush 着色，因此保留透明轮廓并随五个现有主题立即换色，不硬编码独立色板。图标没有点击操作，不混入删除/连接命令。

## 3. 布局实现

在 MainWindow.Resources 定义两种基于现有主题 Button 样式的局部样式，明确覆盖默认 Margin=3；第一枚按钮 Margin=0，其余左侧 Margin=8，避免全局 Margin 与局部 Margin 叠加造成实际间距不一致。

模块信息使用左侧星号列，按钮使用右侧横向容器。文字在可用宽度内截断并保留完整 ToolTip；只让信息区域随窗口宽度变动，右侧六枚按钮占用固定尺寸。

页脚改为独立状态、版本与按钮列，状态过长用省略号及 ToolTip。右侧四枚按钮不与状态文字共享自动宽度，从而避免进度、回退版本长短及“已最新”改变按钮坐标。在当前 MinWidth=1080 及常用宽度验证无重叠。

## 4. 状态和命令

拆分应用“查新”和“更新”命令：查新只调用 CheckApplicationUpdateAsync；更新只调用 DownloadApplicationUpdateAsync 及既有确认/启动更新流程，不能在没有目标时偷偷执行检查。

CanCheckApplicationUpdate 要求未忙、未下载待安装、无查新冷却；CanUseApplicationUpdate 要求未忙、未下载待安装且已有 UpdateTarget。冷却只限制查新，发现版本后更新仍可点击。保留现有十秒检查冷却、下载失败重试、手动回退、兼容守卫和用户确认流程。

回退按钮固定 Content=回退，ModuleRollbackActionText / ApplicationRollbackActionText 留作目标 ToolTip 和确认框；下载/后验证提示保留为独立 ToolTip。去掉应用动态按钮文案，避免“检查更新→更新→待重启更新”改变宽度和语义。下载完成后两个动作禁用，状态区说明已下载及重启要求。

第一轮实现检查：文案、顺序、资源绑定、IsEnabled 与事件对应、默认间距覆盖、打包内嵌资源、无旧混合更新入口；仅宿主文件改动。

第二轮实现检查：新增自动回归，检查查新/更新初始、检查中、查新成功/失败、冷却、下载成功/失败及回退忙状态，验证真实事件不会互换；布局实测两排按钮 8 DIP 间距及状态变动后同窗口尺寸坐标不变。模块下载、未知构建后验证和回退目标提示仍在。

第三轮实现检查：完整 Release 构建与既有烟雾回归，隔离库 WPF 渲染五主题、最小/常用窗口尺寸、长状态/长游戏名与图标有无。查看生成图确认清晰、对齐、无重叠；此检查阶段不操作用户游戏、不读写实际存档，也不上传发布资产。

UI 测试使用注入的隔离 MainViewModel 和离屏内容 Measure/Arrange，不启动游戏连接监视，不加载真实用户游戏库。源 PNG 校验与嵌入资源一致；源图保持不变。

## 三轮设计检查

### 第一轮：需求及范围

已完成。对照用户确认的两个顺序和全部缩写，模块“献者”按原要求保留，不改成别的词；右下角同样为“查新”。现有按钮继承全局 Margin=3，必须用局部样式覆盖，统一边缘间距而不只是给部分按钮再加 Margin。图标绑定 IsModuleInstalled，不误用连接状态或适配器加载状态；保留安装语义及悬停文字，不触及模块业务页面。

### 第二轮：状态机与交互

已完成。现有应用按钮同时承担检查与下载，CanUseApplicationUpdate 也混合冷却与可更新状态；必须拆分事件、CanCheckApplicationUpdate 和 CanUseApplicationUpdate，而不是只增加一个视觉按钮。成功查新后十秒冷却不能阻止更新；失败后清除目标，更新禁用、查新按既有冷却恢复。回退目标文案仍用于确认框，固定显示“回退”不会丢失确认目标。模块可下载和下载后验证的原逻辑留作 ToolTip，业务方法不变。

### 第三轮：尺寸、资源与验证
