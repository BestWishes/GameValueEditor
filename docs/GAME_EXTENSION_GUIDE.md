# 新游戏搜索套路与专属模块扩展指南

## 先选择扩展层级

适合通用搜索套路：

- 数值仍以普通内存数据存在，只经过可参数化编码。
- 同一规则能够跨游戏复用。
- 写入不要求调用游戏业务对象、缓存、事件或保存函数。

适合游戏专属模块：

- 搜到的值只是副本、缓存或界面文本。
- 必须按物品、人物或记录的稳定业务键重新定位。
- 必须进入游戏主线程并调用刷新、事件或保存流程。
- 对象布局、方法或函数只对经过验证的构建有效。

尚未证明能够跨游戏复用时，先实现严格构建匹配的游戏模块，不得把某个游戏的偏移包装成通用套路。

## 分析原则

先记录进程树、可执行路径、命令行、窗口和运行时文件，确认实际数据进程。分别验证界面副本、权威运行时状态、刷新链路和持久化链路。UI 变化、模块自己的写入回读或某个 getter 返回值都不能单独证明功能生效。

所有进程指针、对象地址和 RVA 都是会话或构建数据。每次操作重新定位对象；未知构建、对象未加载、线程不正确、旧值异常或超时必须安全失败。

## 模块仓库

游戏模块只在独立的 `GameValueEditor-Modules` 仓库开发。使用仓库脚手架创建目录：

```powershell
./scripts/new-game-module.ps1 `
  -Game example `
  -ModuleId game.example `
  -ClassName Example `
  -GameDisplayName "示例游戏" `
  -ModuleDisplayName "示例游戏专属修改模块" `
  -ProcessName ExampleGame `
  -ExecutableSha256 <SHA256> `
  -GameAssemblySha256 <SHA256> `
  -MetadataSha256 <SHA256>
```

脚手架只创建当前游戏目录，不修改宿主、中央解决方案或游戏列表。生成的适配器默认拒绝所有构建，开发者必须完成真实定位和验证后才能启用。

新模块必须实现 `IGameAdapter`、`IGameEditorPageFactoryProvider` 和 `IGameCompatibilityDiagnosticsProvider`，并按需要实现库存、人物属性或实体编辑接口。模块为每个稳定编辑器 ID 创建完整 WPF 页面，自行决定 XAML、布局、ViewModel 和交互；主程序只提供页面容器、主题、生命周期、通用输入/错误弹框和保存字段服务。Host API 7 模块必须使用 SDK 的主题资源键和间距常量，不能硬编码独立配色、替换全局资源字典或创建自己的主题窗口。模块包不能携带宿主 DLL 或第二份 SDK DLL。

模块版本与主程序版本分别独立递增，但 `module.json` 必须为每个版本声明 `hostApiVersion`、`minimumHostVersion` 和可选的 `maximumHostVersion`。安装、更新和手动回退都同时核对这个主程序范围、Host API 与当前游戏构建；版本号高低本身不能证明兼容。

只有能对未知构建安全拒绝并给出只读诊断的模块，才可在清单中声明 `supportsUnlistedBuildValidation: true`。此声明仅允许目录未精确命中时下载最新版候选，不能直接启用页面：首次安装在当前离线进程调用 `Supports`，替换已加载模块则重启后再验证；校验失败必须保持停用。存在尚未验证的固定布局时必须拒绝未知构建，符号存在不能代替完整布局与行为证据。未登记构建不提供猜测的手动回退版本，已登记的精确构建始终优先。

兼容性诊断提供器只用于读取并说明构建识别、运行时入口和页面前置条件。它不能写入游戏内存、触发刷新/保存，也不能返回本机路径、用户名、PID、内存地址或存档内容；异常必须由模块收敛为明确结果，宿主仍会进行脱敏和异常隔离。

自有页面注册只报告 Information，不代表当前构建所有功能可用。提供器必须把背包、人物等能力分别说明；不支持的页面使用 Warning/Failed，不能把注册成功当成运行通过。固定偏移不能仅凭短函数序言放行未知构建；实际入口在任何分配、远程调用或写入前验证完整运行文件组合及进程实例。

完整契约、目录、清单、测试和发布规则见模块仓库的 `docs/MODULE_EXTENSION_GUIDE.md`。

## 通用搜索套路

新增套路时使用稳定 ID，并把倍率等变化保存为参数。首次扫描、再次扫描、试改和已保存字段必须使用同一编码/解码实现。候选预览数量不能成为后台数据截断上限。

至少验证：整数边界、浮点异常、非法参数、溢出、大候选集、最后一个分区候选、撤销和进程重建清理。

## 完成标准

- 稳定模块、编辑器、实体和字段 ID 已确定。
- 精确构建指纹或完整语义结构验证已记录。
- 写入在正确线程执行并触发所需刷新/保存流程。
- 持久化功能经过重启验证；会话功能明确不可锁定和自动重应用。
- 人物面板、技能消费、经验结算、掉落实物或其他最终消费者至少有一项直接证据。
- 模块 Schema、构建、真实宿主加载、包内容和 SHA-256 全部通过。
- 兼容性诊断为只读，且复制报告不包含本机路径、用户名、PID、内存地址或存档内容。
- 游戏专属实现、实机测试和分析文档全部位于自己的模块目录。
