# 操作隔离、资料存储、数值边界与更新恢复修复设计

日期：2026-10-06。用户批准修复上一轮只读检查的 7 组问题，并要求先方案、三轮设计检查、实现、三轮实现检查、同步文档、最后提交发布。

预计范围：主程序 0.4.6 → 0.4.7；WorldApart 1.3.2 → 1.3.3；放置斩魔录 2.1.2 → 2.1.3。Last Epoch 0.5.4 二进制不修改、不升版。Host API 7、目录 Schema 5 和稳定模块/编辑器 ID 不变。正式版本仍按各自远端最新标签确认。

状态：详细方案、三轮设计检查、实现与三轮实现检查完成；等待干净提交后的正式产物验收与发布。

## 1. 产品方向与实施边界

保持独立十进制版本、每组最多 3 个正式包、明确宿主/API/构建兼容关系、用户手动回退、模块自主页面、宿主统一主题。恢复同一次失败安装的原文件不等于自动选择旧版本，不能增加自动版本回退。

本次不改真实游戏数值、存档、业务偏移、资源分类或页面布局。验证使用当前测试进程、隔离游戏库、虚拟应用目录和真实模块包；编译实机测试但不自动执行游戏写入。未知构建不补猜测偏移。

## 2. 游戏操作身份与扫描结果归属

新增通用操作上下文，捕获界面代数、游戏/版本引用、已连接进程、关联游戏 ID 和会话引用。游戏/版本/连接切换、清空扫描及退出使旧操作失效；A→B→A 也不能接纳第一次 A 的迟到结果。

手动入库在等待哈希前捕获上下文，返回后先验证，再修改捕获的游戏与会话。失效操作取消，不写新的活动会话、不新增错误绑定、不用迟到状态覆盖新页面。自动入库已有指纹复用保留。

扫描冻结发起时的输入、比较条件、目标类型/套路及源候选。结果、进度、失败和 finally 的界面更新只属于原操作。工作线程已完成但回调未运行时发生切换，结果仍应拒绝并释放临时存储；仅取消令牌不足以证明结果有效。

每个扫描代有独立身份，绑定真实进程实例（PID + 句柄创建时间），预览候选携带该代身份。再次过滤、保存候选和写候选都核对所属代和进程实例；不能只按地址或当前 PID 执行。撤销恢复同一代身份；正常切回仍存活的游戏可继续使用其原会话结果，不把界面代数作为地址永久有效期。

进程内存访问器从实际打开的进程句柄读取创建时间，以免 PID 被复用后把旧候选用于新进程。源存储在过滤期间获得读租约，切换/清空时的 Dispose 延迟至租约释放，避免把取消变成损坏临时文件；最终清理只针对该扫描自己的目录。

检查同类已保存字段、模块异步返回和倍速入口，冻结原服务/目标对象，过时返回不得覆盖活动页面。已发起且针对捕获对象的结果不能误认成新页面的数据。

## 3. 游戏库单写入与有效备份

保存调用在等待之前捕获完整 JSON 快照，异步期间不遍历仍可变的界面集合。相同库路径的 Load/Save 使用进程内串行门禁和有界等待的文件锁；不同 ProfileStore 实例和多个进程不能同时替换同一文件。文件锁只保证文件完整性，不宣称自动合并两个独立程序的编辑。

临时文件使用唯一名字，在同一目录写入、刷盘后原子替换；不再共享 library.json.tmp。替换前只把经完整读取、格式与结构验证的主文件作为备份。主文件缺失或损坏时优先读取有效备份；恢复后的第一次保存不能把坏主文件覆盖到有效备份。

主文件和备份都不可用时明确报告错误，不静默建立空库并覆盖证据；二者都不存在时正常创建新库。JSON null、缺失的必要集合、超出支持的数据 Schema 等按不可安全读取处理。所有失败只清理本次临时文件，保留有效主文件/备份。

## 4. 整数与有限浮点语义

Int32/Int64 输入解析为 BigInteger 有理数，不经 double 中转，也不让 decimal 对超长小数静默舍入。比例参数使用 decimal 拆成精确分子/分母，乘除必须整除且在目标整数范围内；展示使用 decimal 保持整数精度。直接数值可精确往返完整范围，无法表达或运算溢出时拒绝，不绕回、不悄悄舍入。

增加/减少按实际类型比较；Int64 始终比较 long。Float/Double 输入、比例运算结果必须有限，拒绝 NaN、Infinity 和解析溢出；Float 强制转换后再次核对有限性。保留正常小数、科学计数法和原有合法比例套路。

## 5. 当前可信更新引擎与持久事务

更新和回退都复制当前安装目录里的更新器到独立 runner，不从目标旧包提取执行器。目标 ZIP 仍校验路径、大小和摘要；目标版本自带更新器只是待安装文件，不负责执行本次替换。当前更新器缺失时明确拒绝，不降级到旧包执行器。

事务状态持久化区分 Applying 与 Committed。应用文件改变前保存空恢复记录和恢复标记；每个文件备份刷盘、恢复条目刷盘后才替换。强制终止时，标记或未完成事务均能阻止新任务和危险清理。旧格式没有状态的 recovery.json 按未完成处理。

进入替换前把 pending-update.json 移至事务内，避免目标旧宿主下次启动自动重新应用相同任务。事务外保留可独立使用的当前 runner；失败通知提供手动 --recover。安装成功先刷盘记录 Committed，再清除同次标记及归档待安装任务；仅可清理已提交、身份正确的事务，不把更新成功后的残留误判为需要回滚。

恢复先验证整份记录、备份、应用身份、路径、链接和用户 data 保护，再逐项复制原文件或删除本次新增文件。所有恢复完成前保留备份；重复恢复失败仍保留。恢复成功清理同次状态，不恢复 pending 为自动待安装任务。

宿主启动不仅识别恢复失败标记，还只在自己的应用根目录顶层查找未完成事务。未知或损坏事务保守阻止安装并报告恢复位置；正常安装成功、失败完整恢复、提交后清理失败分别有明确收尾路径。任何安装失败恢复不是版本自动回退。

## 6. 回退前二次兼容验证

待安装记录增加目标 Host API 范围和目录 Schema 上限等已验证兼容信息。下载前保持原检查；准备重启时重新读取安装记录；独立更新器等待宿主退出后、修改任何应用文件前再读取当前模块清单并核对目标版本范围/API。

检查逻辑以无 WPF/SDK 依赖的共享源码供宿主与更新器复用，不修改公共模块协议。已安装记录存在但清单缺失、损坏、身份不一致或路径不安全时拒绝，不静默跳过。旧待安装记录缺少兼容信息时，仅允许从 SHA-256 已验证的新 ZIP 内 release-compatibility.json 取得完全一致的目标信息；旧包也无清单则要求重新下载，不能猜测范围。

实现时补充迁移边界，并从三个角度复核：旧 0.4.6 下载新 0.4.7 的 pending 不含新字段，必须由新包清单衔接，否则旧宿主永远无法升级；清单必须唯一、限定大小、版本与目标一致，已有 pending 信息还必须一致，不能放宽验证；打包与索引生成同步校对清单能力，新增的只是包内数据，不改变 SDK/目录协议。另以共享跨进程模块变更锁覆盖安装登记、卸载登记、包清理、应用替换与手动事务恢复，避免检查后再被本程序另一实例更改。

模块下载/安装仍由用户发起；不根据主程序目标自动降级模块。不兼容时列出需要用户先处理的模块，不替用户决定回退哪个模块。

## 7. WorldApart 未知构建守卫

移除“完整运行时哈希不匹配但短函数序言匹配则套用旧布局”的放行分支。允许三文件精确匹配；保留仅启动器变化、GameAssembly 与 metadata 同一已登记记录完全一致的路径。

运行时实际文件验证必须在任何分配、远程调用或写入前完成，并绑定实际进程启动实例和加载的 GameAssembly 路径。缓存不跨实例复用，不能用同一路径长度/时间缓存替代新进程核对。保留已验证两个布局，不改业务对象偏移。

诊断明确区分已登记运行时、启动器差异、未知运行时拒绝；README 不再声称短序言等于完整布局证明。增加完整匹配、仅启动器变化、缺项、跨记录拼接、未知运行时和直接读写入口的安全拒绝用例。

## 8. 诊断的事实层级

宿主对模块自有页面仅报告“已注册；实际运行兼容由模块检查”，使用 Information，不再一律 Passed。不能通过 Kind、ID 后缀或页面内部控件猜支持情况，也不为检查而加载会写游戏的页面。

模块已有只读诊断提供器负责能力差异：放置斩魔录分别报告背包和人物属性构建支持，两个旧布局的人物属性明确未支持；当前支持布局说明已支持的构建事实，不把尚未实际运行的页面读写标成成功。WorldApart 同步精确守卫的拒绝原因。无需新增 SDK 接口或强制其他模块升版。

## 9. 回归矩阵与验收门槛

1. 操作隔离：入库 A→B/A→B→A、断开与关闭；扫描工作完成但回调延迟、迟到进度/错误、切版本、清空；旧候选用于新代/新实例被拒绝，撤销与正常切回可用；过滤取消期间租约释放无残留。
2. 存储：同实例/多实例并发保存、独立进程锁、快照捕获后集合变动；坏主文件有效备份、缺主文件有效备份、双坏文件拒绝、首次创建、未来 Schema 拒绝；每次失败后验证文件内容而非仅验证没有抛错。
3. 数值：Int64 最小/最大、2^53±1、整数增加/减少 1、比例与非整数目标、decimal 溢出、普通浮点、小数/科学计数法、NaN/Infinity/1e999 拒绝。
4. 更新：正常替换、短锁、安装失败恢复成功、恢复再次失败、强制终止于已替换部分文件、重复恢复、提交后残留、缺当前更新器、目标旧更新器不执行、data 不变、非法路径整份拒绝。
5. 兼容：下载前可用而执行前新增不兼容模块、缺失/坏清单、上限/下限/API、旧 pending 缺兼容信息、正式包当前组合；不进行自动模块回退。
6. 模块/诊断：WorldApart 已知/未知与拼接匹配、实际入口安全拒绝；放置斩魔录人物能力差异；自有页面注册不能显示兼容通过；脱敏保持。
7. 发布：完整 Release 构建、宿主烟雾、三个真实模块包、模块 Schema/视觉规则、脚本语法、版本进位、0–5 保留模拟、正式 ZIP 启动和打包更新器沙箱。对真实游戏效果未验证的部分如实说明。

## 三轮设计检查

### 第一轮：方向、范围与契约

已完成。逐项对照只读报告的 7 组问题与实际入口：扫描/手动入库、ProfileStore、MemoryValueCodec/MemoryScanService、Updater/ApplicationUpdateService、WorldApart 构建分支、诊断提供器、主程序回退待安装记录。每组都有对应改动和验收用例，没有把功能布局或游戏业务写入纳入本次重做。

核对两仓库公共 SDK 及旧模块能力：诊断分层可以使用现有 Information 和既有只读提供器，无需新增接口或提升 Host API。WorldApart 保留运行时两个文件完全一致时的启动器差异支持，不把严格验证误实现成游戏目录固定。三份发布二进制是最小必要范围，Last Epoch 不因宿主变动被迫升版。

### 第二轮：时序、故障与数据安全

已完成，并补充四个边界。源扫描读租约必须在任务排队前取得，不能等工作线程运行后才取得；全局 Busy 按当前扫描任务身份释放，但旧任务不能更新新页面进度/状态。读取未来 Schema 的有效文件应直接拒绝，不能回退旧备份并覆盖未来数据。

恢复标记与空事务记录必须早于任何文件替换，pending 移入事务后不能在恢复成功时重新成为自动安装任务。Committed 事务不得当作未完成事务回滚；清理失败仅保留成功事务证据。宿主的启动恢复门禁要在 MainWindow 和游戏库加载前执行，不能只写 crash.log 后继续启动混合版本；旧宿主无法获得新启动代码，因此独立恢复 runner 和取消旧 pending 是必要的兜底，不宣称可以改写历史旧版本。

核对现有测试脚本的短锁/双锁/非法路径夹具，以及启动 catch、旧 pending 和 PrepareUpdaterRunner 的现有调用，确认新增用例需覆盖这些真实边界而非只调用私有判断函数。

### 第三轮：兼容、验证与发布

已完成。远端带注释标签已核对，唯一下一版为宿主 0.4.7、WorldApart 1.3.3、放置斩魔录 2.1.3。模块既有最低宿主 0.4.4/API 7 可保留；待安装的内部兼容信息由当前宿主写入、当前引擎读取，不扩大 SDK 或服务器 Schema。

核对正式打包脚本的干净提交要求，因此三轮实现检查先使用明确 review 文件名的开发测试包，源码提交后再重建正式包并重复产物验收；不能为了打包提前提交未经复核的代码。模块目录只在资产验证后 CatalogOnly 更新。发布保留分别为宿主 0.4.7/0.4.6/0.4.5、WorldApart 1.3.3/1.3.2/1.3.1、放置斩魔录 2.1.3/2.1.2/2.1.1，Last Epoch 保持原三份。

补充校验脚本自身的范围：模块视觉检查改用 Git 文件清单后对精确源文件运行 rg，避免发布链路隐含跨目录递归扫描；未跟踪源文件也要纳入，输出目录仍按 Git 忽略规则排除。验证矩阵既包含既有烟雾/模块生命周期/更新器锁测试，也必须加入本次 7 组边界用例。真实游戏读写不在本次验证授权范围，不以构建成功代替实机生效证据。
