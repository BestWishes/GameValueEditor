# 0.5.2 发布集成（2026-10-09）

用户已确认本地完整测试包并授权提交和发布。本次主程序 0.5.2，Last Epoch 0.5.6，远征首次正式发布 0.0.6；主程序/API 与模块版本独立。远征此前 0.0.5 是本地迭代版本，不覆盖任何同版本资产。Host API 8、库 Schema 7、目录 Schema 5 不变。远征最低主程序提高到 0.5.2，因为正常启动器路由、包指纹和会话页面保留需要本次宿主实现。

## 详细方案

1. 核对两个仓库的 main、origin、远端标签与资产；保留旧包。集成此前已授权并交付测试的名称优先识别、通用进程路由/倍速、页面会话保留/串行读取、离线 review 组合，以及 Last Epoch 当前元数据定位和远征三页动态定位。游戏专属逻辑不加入主程序。
2. 修复已复现的测试收尾问题：模块生命周期测试先报告任务完成，后台 STA Dispatcher 还没退出，进程便进入 WPF AppDomain 清理。返回任务必须等待原测试完成、Dispatcher 关闭及线程退出；保留所有断言、异常和清理，不改生产行为。
3. 同步主程序、更新器、核验器与发布入口版本；模块清单/默认项目版本同步；正式远征包补齐维护者贡献资料。将历史研究测试依赖的工作区脚本保存为只读文本夹具，测试不再依赖私人目录，不能执行该历史夹具。
4. 运行源码构建、完整宿主冒烟、独立页面退出回归、两个修改模块的自动回归、Schema/离线/保留测试。提交源码后，正式包从干净提交重新构建，核对二进制提交号、标准六文件包、模块两文件包、真实模块页面、启动和更新器恢复。
5. 先发布宿主，再发布两个模块；逐资产 VerifyOnly 确认大小/SHA-256。资产验证之后更新 release-index/catalog 并单独提交推送；核对公开 raw 文件。主程序与每个模块最多保留三个正式 Release/资产，保留标签；完整离线包仅本地生成，不上传 GitHub。

## 实施前三遍检查

1. 需求：此次发布包括用户已测试的整体本地改动，不把仅检查的不问凡尘说成修复，也不更新万里仙途模块；不操作游戏或存档。
2. 技术：名称只负责游戏归属，运行对象地址由模块从当前实例解析；宿主维持通用接口、页面生命周期和串行协调。修复的是测试线程收尾，不删断言、不把退出异常当通过。
3. 发布：远端主程序最新 0.5.1、Last Epoch 最新 0.5.5，下一版分别为 0.5.2/0.5.6；远征没有远端标签。先有验证资产再更新目录，避免用户发现不存在的包；旧测试包和正式资产不覆盖。
