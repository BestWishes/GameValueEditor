# 启动器背后的游戏进程与通用加速 · 本地修复

## 依据与范围

2026-10-08 当前游戏由 32 位 `PlayAgainExpedition.exe` 启动临时目录中的 64 位 `ZsebExpedition.exe`，后者另有 renderer、GPU、网络和音频进程。旧 `ResolveLogicalGame` 只沿相同 EXE 路径归组，因此选外层启动器后仍把启动器当作数据/加速目标。模块自己能定位原游戏，不代表宿主通用加速也定位正确。

只读调用既有计时入口发现方法：启动器 0 个、原游戏主进程 14 个、renderer 7 个。前一版与材料修复版的宿主 EXE 哈希一致；此次不是移除了加速，而是模块接入与宿主进程路由没有统一。没有以入口数量冒充实际加速效果。

## 详细方案

1. 在宿主现有逻辑进程组解析器中增加“专用启动器 → 唯一自解压 Web 游戏实例”的解析，不新增玩家启动参数、入口或按钮，不硬编码游戏名字/PID/Steam 安装目录。
2. 候选必须是 Electron/NW.js 主角色、处于临时目录、不同 EXE 路径，且父链能用既有启动来源校验证明归属当前专用启动器。创建时间、有限深度、循环、公共启动器排除沿用原保护。多个游戏实例明确拒绝，不能按内存大小或名字猜一个。
3. 逻辑根仍是实际运行时主进程，数据进程仍是该实例的 renderer；启动器只作为选中种子/来源，不混入数据成员。选择外层启动器、实际主进程、renderer 都应得到同一个会话，另一安装/实例不合并。
4. `AttachedProcess`、通用扫描和加速沿用同一实际数据进程。旧地址、版本和构建指纹不迁移或放宽；进程重建/退出沿用原生命周期。材料、大转盘、掉落及 Host API 不改变。
5. 增加纯进程快照回归：Steam/下载入口的专用启动器、各种选中角色、多个实例、公共启动器、过期父 PID、缺失时间、循环/过长父链、非临时/非 Web 子进程和原同 EXE 行为。
6. Release 全解构建、宿主完整回归、真实游戏只读路由校验。通过后用宿主实际连接/倍速逻辑短暂验证倍率与回正，验证游戏页面计时变化；不发起或停止战斗、不抽奖、不改材料/规则、不调用游戏保存、不操作画面。不建立测试的外部 TCP 监听。材料修改的空闲限制不应移植成加速限制：当前游戏已进入存档且转盘没有待结算奖励时，可验证正在运行的计时；测试后立即回正，游戏原有自然进度不回滚。
7. 使用既有本地 review 构建入口及发布校验流程，正式入口拒绝未提交源码的约束不改。新目录交付本地宿主测试副本和已验证的原四个模块，保留原程序/库/发布包。当前工作版本仍标为本地 review，正式版本号和发布记录暂不改，不提交、不上传、不发布。

## 编码前三遍检查

- 第一遍（方向）：修复宿主的共用进程路由，而不是让玩家改入口，也不只为加速临时挑一个 PID。模块已有的真实进程定位不是宿主连接正确的证据。
- 第二遍（安全）：只认专用启动器、唯一 Web 游戏主实例和有效父链。Steam/浏览器/命令行等共享来源不归成一个游戏，不能跨不同实例。根的存活时间与数据成员边界保持一致。
- 第三遍（验证和交付）：区分路由、挂钩成功、计时生效、回正和实际游戏行为证据；先隔离回归后实机短时验证。沿用正规本地构建/启动/更新器校验，不覆盖正式包或用户安装。

## 编码后三遍检查

1. 第一遍（源码与合同）：跨 EXE 解析限于专用来源与唯一临时 Web 主实例，根及成员以实际运行时路径归组，来源不加入数据成员。原数据进程选择、PID/创建时间校验、构建/版本隔离和模块门禁不放宽；没有硬编码本机游戏路径或 PID。原有本地未提交的游戏身份功能保留，没有重置其他改动。
2. 第二遍（回归与实机）：新增 55 项纯快照路由检查通过，Release 全解构建 0 警告/0 错误；完整宿主 SmokeTests 两轮通过，包括实例可靠性、97 项游戏识别、89 项生命周期、扫描、写入验证、分数倍速/压力、窗口关闭、界面与后台操作回归。正式模块的实机集成 15 项检查通过：从原 Steam 启动器经真正宿主 `Attach` / `AccelerateGameAsync` 接到 renderer，页面 `performance.now()` 相对墙钟比率为 1.0013 → 1.9999 → 0.9999。回正、正常启动参数、原实例和接口清理均确认；未执行抽奖/战斗控制/材料与概率写入或保存。该证据验证页面计时，不冒充逐项实战收益/掉落结算验证。
3. 第三遍（本地交付）：使用现有本地 review 构建入口，正式干净提交发布约束未改变。标准候选启动及更新器沙箱回归通过；新独立应用中四个游戏包由真实宿主验证器加载，所有已注册内容页创建通过，新 EXE 独立启动 5 秒未退出。旧安装、用户游戏库、正式包、模块目录与 Git 历史没有被替换。

首次实机夹具把材料的“空闲”限制误用于加速前置条件，因此只读拒绝并关闭临时接口，没有改速度。更正为验证已进入游戏且无转盘待结算，不替玩家开始/停止战斗。另一次夹具回正早于宿主两秒冷却：退出时 `Shutdown` 已回正，随后夹具改为等待真实按钮恢复可用，不绕过冷却；最终完整验证通过。这两项为测试夹具问题，不是新增玩家限制。
