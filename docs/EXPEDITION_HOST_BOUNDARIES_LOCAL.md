## 详细方案

1. **保守的通用进程归组**：跨 EXE 的解包启动器转向仅限无游戏窗口的 Native/Unknown 主进程；已识别 Unity 等引擎及已有窗口的程序不转向。子运行时须是带窗口、有效启动时间、受限祖先链下的 Electron/NW.js 主进程，并有同 EXE renderer。多个候选只报告歧义，不按内存大小选择游戏实例。窗口、Temp 与祖先链仅是候选证据，不宣称证明游戏语义；用户显式选实际进程的路径保留。
2. **包指纹完整传递**：宿主兼容声明增加可选 packageSha256，从当前构建和历史版本传入目录选择、更新、手动回退及本地已安装构建比对。声明包哈希后，缺失或不符必须拒绝精确匹配；未声明时保持旧原生/IL2CPP 模块行为。诊断展示包对照，不增加游戏字段或 SDK/API 号。
3. **歧义的恢复入口**：候选发现跳过无法唯一归组的启动器，继续提供真实进程；连接前收集已验证实例，多实例要求明确选择。关联窗口捕获预期归组歧义，清空旧详情、禁用确认，给出选择实际进程的说明，不能用勾选绕过。
4. **连接失败回滚**：只为受影响游戏建立连接前检查点，保存版本对象、字段成员与版本元数据；失败后恢复原身份、路径、时间、版本集合及元数据，移除连接中新建的版本（不论是否迁入语义字段）。保留原对象引用与其它游戏，不重写已损坏的磁盘资料。取消/切换选择也不能把未持久化身份留作成功。
5. **昂贵的只读模块检查后台化**：在 UI 线程冻结适配器列表，后台执行 Supports 与版本元数据读取，返回后复核操作代次、会话、进程和模块仍有效。连接复用已准备结果，避免重复散列。模块重载和 renderer 重建期间先撤下旧页面，校验通过再恢复；关闭/换进程后的迟到结果丢弃。不能用缓存省略写入前的实际构建核验。
6. **完整本地包**：复用标准 review 包及既有完整离线工具，增加明确的本地输入参数：review ZIP 必须显式 SHA-256，新增本地模块 ZIP 按 schema/能力/清单/散列校验。目录中的既有模块仍按最新兼容快照选取；不伪造目录、发布索引或已提交证据。本地输出须新文件名，说明与外部核验记录明确 LocalOnly；仍做实际 DLL/页面加载、ZIP 完整性、启动及二次 VerifyOnly。ZIP 不含用户游戏库、存档、运行缓存。
7. **文档与 skill**：同步识别、启动器、发布和架构文档。游戏分析 skill 只吸收角色分离、研究入口与产品入口分离、最终消费者验证、独立概率命名空间、结果不确定不重试等通用经验；不记录游戏名、端口、固定地址或字段。

### 第一遍：方向与需求

已对照 ProcessService、身份证据、模块兼容服务、模块包以及 SDK 合同：宿主不识别某个游戏名，不加入字段、概率规则或 Node 激活代码。Steam 不作为必需条件，正常游戏启动与实际进程选择仍可使用。保留三个内容模块、现有主题和按钮布局。

### 第二遍：失败与生命周期

对照连接、关联窗口、模块重载和 renderer 重建路径：候选歧义不能阻止人工选择；未保存的新语义字段版本也必须回滚；包哈希声明缺值不能算精确匹配；后台结果必须复核有效期。模块写入核验及宿主协调锁不削弱；不对原游戏执行测试写入。

### 第三遍：验证与交付

将增加纯进程快照、包哈希、迁入字段后保存失败、关联窗口歧义、后台回调/迟到结果回归，并执行完整 Release 构建与冒烟、模块纯隔离测试、打包失败边界、实际四模块页面创建、标准 review 启动/更新器以及完整 ZIP 二次核验。已发布 ZIP/索引/目录和两个仓库 HEAD 要保持不变。离线测试不等同原游戏全部效果验证，最终由用户测试后决定发布。
