# 解锁与整页刷新边界（2026-10-07，本地方案）

## 范围

用户批准修复只读复查确认的三项：模块停用但游戏仍连接时无法解锁；模块自主页面迟到的整页读取显示旧值；旧式宿主页面停用后仍回填数据和完成提示。保留两仓所有已有改动，不提交、推送、发布、关机、递增发行版本或覆盖现有 ZIP/catalog；不连接真实游戏。

## 详细设计

### 解锁是取消意图，不是游戏写入

- 启用锁定继续遵守进程、目标、字段策略与协调能力检查。解除已有锁定不需要当前模块可加载、进程可访问或地址可重新解析。
- 可用且身份匹配的适配器归一旧 ID，按规范语义键同步别名；没有匹配适配器时按资料中的模块 ID/键匹配，至少解除选中字段。原生字段在可访问时保持实际地址别名识别，访问失败则按已保存的等价定位匹配，不猜跨构建地址。
- 解除时旧队列失效是尽力通知，不能让通知失败阻止清除锁定目标和保存资料。后台仍检查锁定标志/目标及取消信号；已经进入同步写入的调用不能声称撤销。
- 保存失败继续如实报告，不声称持久化成功；不删除字段或自动解除无关目标。

### 整页读取使用模块快照，不把所有字段写入串行化

- 在现有 PID/启动时间/构建范围内，为每个规范模块 ID 维护递增修订和待完成写入计数。写请求入队及释放均改变修订；已排队但取消的写请求也必须等前驱结束才释放计数。
- 后台维护仅真正需要写入时登记模块变更；只读巡检不使整页数据失效。不同模块/游戏范围隔离，现有字段 FIFO 和原生重叠规则不变。宿主无法从原生地址推断模块语义关系，不扩大这个承诺。
- 新增独立 SDK 能力 `IGameEditorSnapshotOperations.ReadSnapshotAsync<T>(Func<T>, Action<T>)`。读取在后台执行，结果应用在原 Dispatcher 上。快照必须在读取开始时无未完成写入，并在结果应用时修订未变、仍无未完成写入。
- 快照验证与同步 UI 应用位于同一短临界区，避免宿主验证后、模块应用前又发生写入。UI 应用只替换页面数据/选择/完成提示，不进行游戏调用、等待或资料保存。
- 读取期间有相关写入、迟到错误或快照开始时仍有写入，则丢弃结果/错误，提示“模块数据已变化，本次刷新已忽略，请重新刷新”。不自动重试、不自动回退、不重新加载模块。
- 页面生命周期和原适配器失效仍优先取消；停用提示不被旧刷新提示覆盖。共享背包/人物/实体页及 Last Epoch 资源页统一使用快照能力，保留模块自主布局、主题资源、现有分类及无“全部”的资源列表。
- Host API 8 尚未发布，本轮补全这个草案能力，不另造 API 9；既有服务接口、页面上下文构造和 CLR 程序集标识保持不变。新源码页面缺少快照能力时明确要求更新宿主。旧 API 6/7 不可变包仍按原兼容路径加载，不能声称其直接读取自动接入新能力。

### 旧式宿主页面

- 背包、人物、实体三个读取入口使用同一快照应用规则，并在成功、异常及完成提示之前核对原适配器实例、游戏操作上下文。
- 模块停用/替换后抛出正常取消，不再填充列表或显示旧错误。写入后的后续刷新也保持原适配器检查，防止刷新间隙停用后仍显示修改完成。

## 编码前三遍检查

1. 方向与兼容：已核对两仓 SDK、实际共享页面和资源页面、Host API 8 本地状态及旧 API 1–7 分支。只补数据边界，不更改 UI 模板或发行资产。独立能力接口避免修改已发布的旧服务 ABI。
2. 并发与失败：已核对 FIFO 取消释放、维护真正写入位置、页面 Dispatcher 返回与应用之间的间隙，以及停用/保存失败路径。采用写入计数加首尾修订、原子同步应用；解锁按取消意图处理，不把进程解析作为必要条件。
3. 验证与交付：先加入回归在旧生产代码上验证解锁/旧式迟到读取失败，再实施。覆盖四种真实页面、新写入/进行中写入/迟到错误/停用/不同模块/后台维护/取消释放、别名解锁和资料保存失败。构建和测试顺序避免争用 DLL；最终三轮分别检查针对性行为、完整新旧兼容、文档/差异/资产不变。

## 验证限制

快照检测宿主协调的模块写入，不是整个游戏内存的事务快照；游戏自身变化、无法对应语义键的通用地址写入、旧自有页面直接调用不在此承诺内。模块仍负责真实构建匹配、线程、业务保存和最终玩法效果；这些隔离测试不证明实际游戏属性生效。同步调用已开始或资料保存已完成时不能靠取消撤销。缺少匹配适配器时只按已保存 ID/等价定位识别别名，不猜未知旧 ID 归属或跨构建地址。
