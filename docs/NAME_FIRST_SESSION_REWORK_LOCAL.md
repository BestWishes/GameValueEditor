# 名称优先识别与连接页面重做（本地，2026-10-08）

## 用户规则与范围

先按游戏名称识别：同名属于同一个游戏，模块声明的中文名、英文名和进程名为别名。文件指纹不再判断游戏归属；它只记录构建、隔离旧地址。普通小更新不要求重新关联、不因哈希变化关闭整个模块。游戏专属定位留在模块内。修复切换条目丢页面状态及刷新接入冲突。不提交、推送、发布；不覆盖用户正在运行的测试目录，不修改游戏文件、启动参数或旧存档。

## 详细实施方案

1. 名称优先：重写游戏归属解析，精确规范化名称和模块现有名称别名；选中条目在同名记录间优先，不按文件散列/安装路径拒绝同名更新。多个运行实例仍选实际进程，不把多个 PID 当一个实例。保留历史构建与原始地址隔离。
2. Last Epoch 自动定位：删除历史三文件白名单硬门槛，运行入口只确认当前实例及正常 IL2CPP 运行时。资源、存档标记、异界、摄像头、统计对象改为从当前类和字段名解析地址；托管数组/字符串 ABI 与序列化格式不混为游戏字段。原生钩子按当前方法重新定位，不沿用旧 RVA；个别属性确实变化时只显示该属性不可用，不连带其它页面。
3. 页面归连接会话：每个连接保存页面对象、选中内容页、输入、筛选和滚动位置；切换条目只换显示。断开、进程重建、模块替换和退出才释放页面。隐藏页面不能发起写入/弹框/覆盖其它游戏状态；已经开始的只读刷新可回到自身仍有效的页面，不因单纯隐藏作废。
4. 远征请求串行：同一模块所有读取/修改/清理共用串行入口，正常重叠请求等待前一个完整结束。页内重复点击合并，销毁后的排队请求不开始。仍保持跨宿主排他性与不确定修改不重发；不将业务操作自动重试。
5. 验收：覆盖名称不变但所有哈希改变、中文/英文别名、非 Steam 路径变化、同名多个实例、切出再切回保留同一页面与未应用值、刷新中切换、反复刷新排队、断开真正释放、重建不复用旧页面。对用户当前更新后的 Last Epoch 做只读实际模块读取，不修改角色材料。运行现有回归并记录实际结果，不把模拟检查说成所有实机修改效果已通过。

## 实施前复核（三遍）

1. 需求复核：用户明确要求名称优先，取消身份解析的指纹/不同安装冲突门槛；版本隔离仍保留。不增加用户配置或启动步骤，不再依赖模块兼容成功才能认出条目。
2. 实现复核：已跟踪 SelectedGame→Restore/Clear→Rebuild→Dispose；页面确实只保存在全局视图中。已跟踪远征 Task.Run→Exchange→FileShare.None，取消 UI 不会终止已运行的同步请求。改为会话持有页面和模块串行入口，分离页面有效期与是否正在显示。
3. 更新复核：Last Epoch 已有类/字段/方法解析能力，但资源、异界、摄像头仍有固定偏移，不能简单删除白名单后直接复用。已从既有 1.5.1.1 结构证据取出字段名称；需将游戏字段替换为当前运行时解析并在当前更新构建实际只读验收。游戏名、字段和钩子都不进入宿主。
