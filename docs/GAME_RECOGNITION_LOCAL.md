# 通用游戏识别与手动关联（2026-10-07，本地实施）

> 历史记录：本文的来源/路径/指纹优先身份方案已被名称优先方案替代。当前规则见 [名称优先与会话页面重做](NAME_FIRST_SESSION_REWORK_LOCAL.md)。以下只保留旧实现和当时产物证据，不是当前连接要求，不再据此要求同名小更新重新关联。

## 范围与现象

用户授权先实现功能，不提交、推送、发布、递增版本或替换正在使用的程序。不修改游戏、存档、用户游戏库或模块仓库。主程序版本仍为 0.5.1、Host API 8、库 Schema 7；新增可选身份线索，旧资料缺失时走保守识别或用户确认，不伪造历史证据。

已只读确认“再刷一把·远征”的固定启动器启动临时目录中的 Electron 游戏；更新前后临时目录、EXE 指纹均变化。旧档案没有启动来源/包身份，现有路径、构建、模块规则都无法证明关联。Steam 只是一项可选来源，修复不能依赖 Steam，也不能退回按进程名合并。

## 详细方案

1. **身份与版本分离。** 新增游戏身份线索：非临时安装/专用启动器路径、运行程序名、程序产品名、Electron/NW.js 包标识和可选平台 App ID。名称、窗口标题、图标不作自动合并依据；包名/产品名只作印证或冲突检查，不单独跨安装合并。已有不同模块身份、不同包/平台身份、多个同等匹配均保守拒绝自动关联。
2. **真实启动关系。** 运行进程组和实际数据进程保持原规则；单独沿有启动时间约束、无循环、有限深度的真实父链寻找非临时来源。公共启动器（Steam、Explorer、命令解释器等）不能成为专用来源，不扩大扫描范围、不把启动器当数据进程。普通下载版直接使用非临时 EXE；临时运行没有可信来源/自身标识时不猜测。
3. **候选发现。** 进程名只是候选线索。已有来源还可发现名字变化的后代；不同安装或候选冲突不凭窗口/内存占用认定游戏身份。同一逻辑实例去重，多个实例沿用实际进程选择与实例核验。
4. **有证据才自动关联。** 固定运行路径沿用，新增线索可发现明确身份冲突；相同专用来源加相同非空包/产品标识可跨更新识别临时运行。已验证模块或唯一完整已知构建仍可支持合法换目录；已有另一安装仍存在时不悄悄合并。平台 ID 为可选线索且必须来自实际安装来源，不把共同的 Steam 父进程当游戏身份。
5. **手动关联。** 游戏库“连接”在证据不足/候选多义时打开主题一致的进程选择框，展示路径、来源和目标条目；需选择并勾选明确确认。可搜索所有当前可访问进程以处理改名/搬目录，候选仅推荐、不授权自动关联。取消不改变会话或档案。返回后再次核对原游戏操作代、条目成员、PID/启动时间；已明确属于另一条目或另一模块的进程不被抢占。新关联仍计算新构建，保留历史版本/字段，不合并条目、不自动迁移原始地址、不放宽模块 Supports。
6. **完整游戏包指纹。** Electron 的 `resources/app.asar`、打包 NW.js 的 `package.nw` 纳入组合指纹并保存包散列；只读取已知文件，不递归散列游戏目录。包身份解析限制头部/JSON 大小、拒绝链接/越界/重复或无效数据；读取失败不把模糊包标识当证据。旧 EXE-only 档案不能证明新包版本，保留为历史记录并建立新版本。
7. **贯通保存与后续识别。** 新建入库、已验证连接、版本匹配共用证据与规则；用户确认的身份线索保存到原条目。证据缺失不能擦掉已保存身份，身份冲突不能自动覆盖。每次新的冲突仍要求明确处理，不把一次确认当永远的通行证。保存失败报告失败，不能声称关联已持久化。

## 写代码前检查（三遍）

### 第一遍：需求与方向

已对照用户确认：Steam/下载版同等支持；临时目录不持久作为安装身份；信息不足必须能确认关联；只在本地实施。旧条目没记录启动来源时不能凭当前来源倒推旧来源，因此本次旧档案允许一次手动关联，不能宣称可以安全自动修复所有历史资料。

### 第二遍：安全与时序

已跟踪库内连接、顶部连接、入库、版本匹配和会话归属。保持逻辑根/数据进程与启动来源分离；PID/父进程创建时间、循环/深度约束防过期链。手动弹框返回后校验原上下文，不根据弹框期间的新选择改另一个条目；取消与拒绝前不 Attach。原始地址继续按构建/实例隔离，模块仍按 Supports 验证。

### 第三遍：兼容与验证

已检查现有纯身份规则、真实测试进程的隔离连接夹具、存储格式门禁和主题弹框。保留原私有连接入口及默认拒绝语义；新增可选线索不提升公共 SDK/Host API/Schema，不修改正式资产。Native/IL2CPP 组合算法在没有包时保持原字节；Electron 包变化必须产生新指纹。新增专项回归，再运行现有完整烟雾与构建，不连接真实游戏、不写游戏内存。

## 实施后验收计划

- 第一遍：逐项源码/差异检查，检查身份冲突、公共父进程、临时路径、数据路由、取消/迟到响应和旧字段保护。

- 第三遍：全部 Release 构建、现有完整冒烟/布局/生命周期/存储回归，检查文档、版本、Git HEAD、正式资产与遗留测试进程。本文件追加实际执行结果，计划不等于完成证据。

## 实施后检查与实际结果（三遍完成）

### 第一遍：实现与安全方向

逐项检查来源采集、候选发现、身份解析、顶部/库内连接、入库、版本匹配、持久化与新弹框。运行组仍只包含实际游戏进程，专用来源不参与会话存活判断；实际连接前额外核对逻辑根 PID/启动时间，数据进程继续执行原实例核验。父链最多 8 层，有时间/循环门禁；候选发现复用进程索引，不为每个候选重复构建全量映射。公共运行程序的 EXE 路径/单独外壳散列不能识别另一个应用。

手动选择后重新取进程快照、计算构建和验证原操作上下文。既有其他条目的明确身份、已验证不同模块身份，以及同一运行实例已登记在其他条目的会话，都会拒绝抢占；不因新包指纹暂时无法解析旧身份就覆盖既有连接。保存失败撤回新路径/身份线索和未保存的空版本，并断开本次连接；已存在的版本、字段和原资料文件保留。缺失元数据不擦掉旧来源/标识，平台名称与 App ID 作为成对线索保留。

### 第二遍：专项隔离验证

新增 `GameRecognitionRegressionTests` 最终通过 **97 项断言**，覆盖固定下载目录更新、无 Steam 的专用启动来源、临时目录/构建同时变化、已知构建换目录、多个相同来源、不同包/产品/平台身份、第二份安装、公共运行程序、过期/循环父链、名字变化后的来源发现、renderer 路由、旧 EXE-only 不证明包构建、ASAR 内容变化/损坏/重复标识/越界/链接、NW.js 包，以及 Schema 7 可选线索保存/读取。

手动关联验证使用自己启动的独立测试进程和 GUID 隔离目录，覆盖取消、确认并重启宿主资料后自动关联、弹框期间换游戏、进程退出、伪造启动时间、其他条目所有权、已验证不同模块身份、已有会话归属和持久化失败。旧两个通用字段始终保留在历史版本，确认后的新版本不复制原始地址字段。原游戏生命周期回归 **89 项**仍通过。

新弹框通过 **31 项断言及 5 种主题渲染**，推荐候选不默认选择/确认；勾选才可连接，换候选/筛选后撤销同意。有明确的筛选标签、目标条目、实际路径、来源和游戏标识。实际检查浅/深色渲染，没有改变原游戏库或页脚布局。

验证中修正两个夹具问题：公共 EXE 的排除规则不应把旧测试使用的同名 DLL 也排除；模块冲突夹具原先只支持测试本身的 PID，没有真的验证子进程的模块身份，现改成明确支持该测试目标的既有样例适配器。无头新窗口检查改为显式控制测试 Application 的关闭模式，恢复 MainWindow/模式并断言 Dispatcher 未关闭，防止影响随后旧分组弹框的 Loaded 回调。没有为通过测试而放宽生产身份或模块门禁。

### 第三遍：完整回归、真实只读核查与交付边界

## 使用说明与限制

2026-10-08 后续边界修复已补充包哈希的目录/已安装声明比对、候选歧义恢复入口、多个已验证实例人工选择，以及包含语义字段迁移和既有版本元数据的保存失败回滚。已成功提交的主文件不会因迟到的页面切换被撤回。旧检查数字与交付记录描述当时产物，当前检查见 [边界复核记录](EXPEDITION_HOST_BOUNDARIES_LOCAL.md)。

旧档案没有记录过专用启动来源/包身份，不能从当前进程倒推可靠历史关系。首次使用这个本地实现时，从原游戏条目点击“连接”，选择实际游戏进程、核对信息并勾选确认；成功后保存到原条目。后续来源及身份线索足够且无冲突时自动识别。搬目录/换来源或线索冲突仍可能再次要求确认；不会声称所有未知游戏都能无条件自动识别。当前正式运行的程序没有被替换，新功能只在本地源码与测试构建中。

构建指纹扩展只覆盖已知 `app.asar`/打包 `package.nw` 文件，不递归遍历松散游戏目录，也不宣称已经为所有引擎完整散列所有脚本/插件。新增线索是 Schema 7 的可选便利信息；旧宿主会忽略这些字段，若用旧宿主保存，可能丢失便利线索并需要重新确认，但不能据此放宽构建/模块兼容性。
