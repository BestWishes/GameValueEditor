# 0.5.3 / 远征 0.1.2：版本、查新回退与发布边界修复

## 范围与详细设计

用户授权修复四项问题后直接提交和发布。仅改变通用候选选择与发布工具；不操作原游戏、修改存档、改变五个远征页面或游戏规则，不重发另外三个游戏模块。保持 Host API 8 / SDK / 资料与目录 Schema 不变。

1. **交付版本统一计数**：主程序 0.5.2→0.5.3。远征本地已交付 0.0.7、0.0.8、0.0.9、0.1.0、0.1.1，不能以最后正式标签 0.0.7 为基数倒退；下一正式版为 0.1.2。模块仓库增加通用本地交付历史，正式标签与已交付版本合并后按十进位 +0.0.1 检查。历史条目记录证据，不伪造正式标签；已有正式资产保持不可变。已生成供交付的本地模块包记录其版本，后续新包不得复用该编号。已有标签的复核/补传仍允许，二进制来源由实际标签核验。
2. **候选选择一致**：先按稳定进程名称找模块，再按 Host API、主程序上下限筛选。保留精确匹配或明确声明动态解析能力的版本，统一按版本降序选择；不把精确匹配的旧版置于支持动态解析的新版之前。对这份候选集合同时确定更新和较低版本手动回退目标。精确匹配状态对应选中的版本，不是“某个历史包匹配”。下载后仍由模块解析当前真实接口；未声明动态解析能力且不匹配的旧包不开放。回退仍需用户确认、安装后重启，不新增自动回退。
3. **候选 ZIP 原子提升**：每次构建使用唯一的工作目录，不删除固定旧构建目录或其它模块 ZIP。两文件包先写到独立候选文件，检查精确文件图、清单及源文件散列，再通过不覆盖目标的原子移动提升。构建/压缩/验证/移动失败均保留历史产物。已经存在的同名正式 ZIP 拒绝重建覆盖，CatalogOnly 只读取已有经过核验的产物。
4. **可恢复且有来源约束的发布**：主程序和模块发布助手共同改为“带注释标签提交属于目标分支历史”，允许目录/文档提交推进 main。保留 DLL/EXE ProductVersion 与标签源码提交一致的检查，并核对远端注释标签对象与本地一致，防止补传到同名异源标签。标签无效或来源冲突应停止，而不是重新创建标签/覆盖资产。

## 发布与验证顺序

1. 源码修改前复核三遍：需求与边界；候选集合/版本与异常分支；产物来源/恢复与保留策略。
2. 增加真实候选选择回归，覆盖旧精确包不能压新版、未知小版本可手动回退、无动态声明的未知包仍排除、宿主不兼容版本排除及本地 0.0.7～0.1.1 到 0.1.2 的更新。
3. 发布工具隔离回归覆盖十进位/交付历史/重复编号，旧 ZIP 与其它游戏包保留、同名拒绝、失败不提升，以及标签等于 HEAD/祖先/分支外/轻标签/远端异源。
4. 实现后复核三遍：逐项差异与负向测试；完整 Release 构建/主程序冒烟与模块回归；从干净已提交源码构建正式产物，真实模块加载、打包 EXE 启动、更新器和离线包核验。
5. 主程序与模块分别提交源码、构建、推送注释标签、上传不可变 ZIP、独立 VerifyOnly。线上资产核验后再更新主程序发布索引、模块目录，各自单独提交推送，复查公开状态。
6. 最多保留三个正式主程序 Release 和每个模块三个正式 Release；先预演再清理，不删除 Git 标签或本地旧包。完整离线包沿用短名，作为本地交付，不上传为 GitHub 主程序资产。

## 方案三遍复核（写代码前）

- 第一遍：四项问题对应上述四项实现，无固定游戏规则进入宿主；两个版本号独立，0.1.2 消除早期同号测试包及高号测试包查新不更新的问题。
- 第二遍：动态能力不等于猜测内存地址；未声明的未知旧包仍排除。更新/回退来自同一集合，手动操作仍有明确确认，不取消下载超时或安装事务。
- 第三遍：打包与远端保留分离；源码、ZIP、标签、目录顺序保持可追溯。旧资产不覆盖，失败不能丢失旧包，标签祖先检查不是允许任意不相关提交。

## 实施后三遍复核

- 第一遍（差异与负向边界）：真实目录服务新增 32 项，覆盖旧精确包/动态新版排序、所有远征本地版本更新、未知构建手动回退、宿主不兼容和严格未知包排除、检查不安装不降级。两仓各 20 项隔离 Git/版本历史回归通过；模块候选 ZIP 故障与并发目标保留 14 项通过。主程序生产差异仅通用候选算法；远征游戏请求、SDK 和其它三个模块源码未改。
- 第二遍（完整源码回归）：主程序完整 Release 构建与完整冒烟通过，四个实际模块 Release 构建均 0 警告/0 错误；远征 UI 363 项、共享真实页面 186 项、Node 概率回归，以及清单/视觉约束、目录 StrictMode 和 Schema 回归通过。测试只使用自有内存、隔离进程与页面；没有连接原游戏、改存档或操作屏幕。
- 第三遍（正式产物与集成）：将在干净提交构建后记录标准包真实启动/更新器、四个原正式模块包的 14 页加载、完整离线包与线上验证结果；通过后才推送发布，不能以本计划代替结果。
