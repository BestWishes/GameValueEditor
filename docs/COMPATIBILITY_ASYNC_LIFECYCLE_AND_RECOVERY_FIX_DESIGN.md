# 兼容、异步上下文、模块生命周期与失败恢复修复设计

日期：2026-10-06。范围：主程序 v0.4.6、Last Epoch 模块 v0.5.4。
状态：详细方案、三轮设计检查及三轮实现检查已完成；通过后提交源码，再从干净提交重建正式包并复核公开发布。

## 依据与方向

上轮检查以隔离用例复现了三个主程序问题：检查游戏 A 时切到 B，A 的响应仍能开启 B 页面的安装按钮；停用模块后卸载另一模块，会把停用模块重新加载；更新失败且原文件恢复再次遇锁时，恢复备份仍被删除。
Last Epoch 还存在静态安全缺口：Supports 忽略传入构建指纹，主要检查符号存在，但资源、异界及摄像头路径仍有固定布局。因此符号存在不能证明未知构建的完整读写安全。

保持现有产品方向：版本独立十进制递增；显式主程序/API/游戏兼容关系；用户手动回退；每组最多 3 个正式 Release；模块自行布局、宿主管理主题；未知构建允许下载的能力与运行兼容结论分离。

## 1. Last Epoch 的完整运行边界

保留 supportsUnlistedBuildValidation=true，使未知构建能够下载模块并获得本地拒绝原因。当前仍有固定布局的整个模块只对包内已验证 EXE、GameAssembly、metadata 三项指纹的同一条完整记录启用。未知、缺项或拼接不同记录的指纹均拒绝；不得仅凭相同 EXE 或同名字段启用。

把 module.json 嵌入 DLL，构建清单是唯一指纹来源，避免另维护一份散落常量。Supports 在打开运行时、执行 IL2CPP 调用前验证传入指纹；其后验证实际进程身份、启动时间、加载的 GameAssembly 路径和真实磁盘三项指纹，防止直接调用读写接口或伪造传入身份绕过边界。

所有运行时构造入口统一经过构建守卫。进程启动时间必须与上下文一致；每次操作检查离线模式及文件路径、长度、修改时间。第一次连接或文件状态变化时计算哈希，缓存只用于同一个进程启动实例及完全相同的文件状态；哈希前后文件状态变化时拒绝。缓存有上限，不持久化地址或 PID。未知实际构建在任何远程分配、IL2CPP 调用或业务读写之前拒绝。

这次不宣称所有未来小版本自动兼容。后续只有完整验证固定布局，或把所有固定布局改为带类型、方法签名与运行约束校验的语义访问，才能扩大兼容范围。当前四条已登记构建继续保留。诊断分别说明离线模式、已验证构建、运行符号检查；未知构建明确提示固定布局尚未验证，页面保持停用。

## 2. 异步模块操作绑定发起上下文

每次检查、安装、更新、回退和卸载捕获游戏、版本、连接进程、会话、构建指纹以及页面代数。切换游戏/版本/连接使代数变化；即使 A→B→A，也不能接受第一次 A 的过时响应。

检查响应及失败状态仅能写回仍与发起上下文一致的模块页。检查结果记录自己的上下文；安装、回退按钮和实际命令均再次核对，不能只依赖按钮禁用。

下载可以在切换页面后继续完成。包安装和登记是全局操作，仍针对最初捕获的模块 ID；原游戏的登记可以保存，但不得把目标模块绑定给后来选中的游戏。进度只更新对应页面，底部全局进度必须明确模块名。完成/失败不得用旧结果覆盖当前页；切换后按当前游戏重置模块检查状态。未入库的连接在下载期间失效时，保留已安装模块并通过正常登记对账创建条目，不把过期 PID 保存入库。

## 3. 等待重启由加载器强制维护

GameAdapterRegistry 保存进程生命周期内的待重启 ID 集合。DeactivateUntilRestart 同时登记 ID 并移除活跃适配器；Reload、LoadInstalledModule、LoadModule 均不能重新装载集合内模块。新主程序进程的注册表集合为空，正常载入已登记目标版本。

记录已加载过的不可回收 WPF 模块身份。卸载后同进程重装仍需要重启，不把“无 installed.json 记录”误当成从未加载。

卸载只停用目标模块，不 Reload 全部其他模块；释放该模块页面和锁维护后删除原包。错误恢复不使用全局重载绕过停用状态。待重启信息按模块说明，布尔提示不能代替加载器约束。

## 4. 更新失败恢复与手动恢复

正常更新/回退继续使用相同事务替换。每个目标文件在替换前保存备份和恢复记录；恢复使用复制，保留备份直至所有文件恢复成功。新增文件记录为应删除项。恢复记录仅包含应用目录内的相对路径，拒绝路径越界和 data 用户目录。

若安装失败但恢复成功，清理事务目录、提示错误并可重启原程序。若恢复再次失败，保留完整备份与 recovery.json，记录 recovery-required.json 及更新器路径，不重启混合版本；错误报告明确备份位置及手动恢复入口。

更新器支持显式 --recover <recovery.json> --app-dir <目录>。用户在关闭主程序并释放占用后可重试恢复；重复失败仍保留备份；成功后删除恢复标记与事务目录。此入口只恢复同一次失败安装的原文件，不是自动版本回退。

主程序更新服务在恢复标记存在时拒绝新更新/回退下载与待安装启动，防止覆盖恢复证据。清理临时更新文件时保留该次恢复所需更新器、记录和包。重启失败提示仍能显示恢复位置；本次不新增自动版本回退。

## 验证矩阵

1. 已知三项完整指纹通过；大小写忽略；空项、未知项、跨记录组合、仅 EXE 一致均拒绝；未知拒绝发生在运行时调用之前；所有读写入口均经过真实构建检查。
2. 延迟检查 A→B 与 A→B→A；切换版本、断开连接；延迟检查失败；过时命令拒绝；下载中切换后只登记原模块，不覆盖新页面。
3. 停用 A 后卸载 B，A 不复活，B 以外模块实例不重建；全局 Reload 和直接加载也不能复活 A；卸载 WPF 后重装要求重启；新注册表能够载入目标版本。
4. 短暂文件锁恢复后安装成功；中途失败完整恢复；安装失败加恢复锁保留备份与记录；释放锁后显式恢复成功；重复恢复失败仍保留；清理不删恢复资产；恢复前不能创建新待安装任务；用户 data 内容不变。
5. 现有下载 60 秒无数据及 20 分钟总超时不变；两种超时都清理本次创建的半成品，未开始写入时不删已有目标文件。烟雾测试、模块清单/主题检查、真实包加载、发布保留模拟、最终包启动和更新器沙盒全部执行。

实现检查中的补充方案：总超时的专用 catch 抛出 TimeoutException 后不会进入后续通用 catch，导致半成品残留。将失败清理统一放到 finally，并仅清理本次已开始写入且未完成的文件；不调整超时政策，不覆盖原始错误。补充方向、失败边界、验证三次检查均通过，加入总超时与默认政策回归。安装未入库进程时复用检查时的指纹，避免自动入库再等待哈希期间切换连接；版本从原游戏的原指纹定位，不读取异步完成后的 SelectedVersion。

## 三轮设计检查

第一轮：方向与授权检查通过。四项均有代码证据或隔离复现；修复不改变用户手动回退和页面自由的决定。未知构建仍可下载，但缺少固定布局证明必须明确拒绝运行；游戏数据和存档无需写入。

第二轮：状态和失败边界检查通过并补充。页面代数覆盖切回同一游戏；安装与回退命令自身验证上下文；加载器维护永久到进程退出的停用集合；卸载重装覆盖已加载 WPF 情况；恢复复制而非移动确保重复恢复仍有完整备份；恢复失败不重启混合安装。

第三轮：验证与发布检查通过并补充。把已有复现升级为仓库回归测试；增加真实构建守卫的无游戏测试；缓存以启动实例及文件状态为键，变更重新哈希且拒绝中途变化；恢复标记阻止新的更新、启动安装和清理证据。预计版本由最新标签唯一递增；最终发布必须独立验证公开元数据后才清理。

## 三轮实现检查

第一轮：静态契约检查通过并补强。所有 Last Epoch 运行时入口在调用前核对实际构建；三项指纹必须在同一记录中命中；SDK 和 ID 不变。检查与实际命令都绑定上下文，卸载完成与迟到进度也不覆盖新页面。自动入库复用原指纹并定位原版本。加载器重载不重建未受影响实例，安装记录消失时停用旧适配器。恢复记录先于替换写入，恢复复制保留原备份，第一次记录写入失败且未替换时不会伪造恢复需求。

第二轮：异常与行为回归检查通过。新增测试覆盖 A→B、A→B→A、同游戏切版本、断开连接、旧检查 404、过时安装命令和下载中切换。用 Last Epoch 测试包与 WorldApart/Fzzml 原正式 ZIP 验证停用后卸载别的模块、Reload/直接加载/同进程重装均不复活，新注册表正常载入，其他实例不变。构建守卫的四条完整指纹和大小写匹配通过，缺项、混合和未知项拒绝。更新器沙盒通过短暂锁、替换失败后完整恢复、安装与恢复双锁保留、重复恢复失败保留、显式恢复成功、三类不安全路径整份拒绝、用户 data 不变；恢复标记阻止新更新并保留资产。新总超时测试发现并修复清理遗漏；无数据与总超时及默认 60 秒/20 分钟政策回归通过。

第三轮：提交前独立复核通过。主程序、全部模块及实机测试工程 Release 构建均零警告/零错误，当前宿主实际加载三个包并核对 5/2/2 个页面；模块 Schema/视觉所有权检查、两仓库脚本语法、0–5 个正式 Release 保留模拟与 git diff --check 通过。版本为唯一下一版 0.4.6/0.5.4；相关 README、架构、扩展规范、恢复说明与历史设计纠偏已同步。游戏未运行，本次不报告新的实机属性或存档验证。此轮使用的是带明确 review 后缀的开发测试包，不能上传；正式包必须在源码提交后重建、核对内嵌提交号、启动测试及更新器沙盒，并在远端哈希、公开目录/索引确认后执行保留清理。
