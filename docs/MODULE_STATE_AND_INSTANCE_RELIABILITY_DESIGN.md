# 模块资料、安装事务、诊断与多开保护（2026-10-07）

发布状态：这些修复纳入 v0.5.0，见[集成复核与发布记录](RELEASE_0_5_0_INTEGRATION_REVIEW.md)。下文保留原本地实施的授权范围、旧版本产物与检查证据，不代表后续用户授权的发布状态；模块仓库未改变。

## 范围

只修改本地主程序与隔离测试，不提交、推送、打标签、发布、递增版本或覆盖现有发布包。保留此前未提交的离线打包、下载反馈和布局改动；不改模块仓库、SDK/API、服务器 Schema、游戏指纹、游戏内存或存档。长期离线核验工具暂不纳入本轮。

## 详细方案

### 1. 模块资料不再“损坏当空”

新增共享的模块资料读写器，供目录服务和运行时加载器使用。`installed.json` 与 `pending-deletions.json` 均检查必需字段、Schema、集合、重复身份、安全路径段及正式版本；未知 Schema 拒绝解释。写入使用唯一临时文件、刷盘和原子替换，保留上一份有效备份；首次写入也建立备份。

不存在主文件且不存在备份才是真正的新目录。主文件损坏、主文件缺失但备份存在、未来 Schema 或读取权限失败，不能默认为空并继续写。保留原文件及备份，诊断显示资料错误，禁止安装、回退和卸载；修复原记录或明确使用备份后重启。备份不自动改回已安装模块版本，也不自动恢复旧的待删除任务。

待删除列表完成后写入有效空记录，而不是删除文件，避免旧备份中的任务再次生效。模块资料错误不能阻止通用扫描和主窗口启动，不能抹掉游戏库中已有的模块身份关联。

### 2. 模块安装成为可恢复事务

仍保留下载大小、SHA-256、清单/身份/兼容和 ZIP 路径检查。变更持有既有跨进程模块门禁，先读取并校验原登记，再在本次唯一事务目录准备包。

准备完成后，将原登记、目标登记、模块身份、目标原先是否存在、包文件散列和 Prepared 状态刷盘。已有同版本目标包用移动保存到事务备份，不预先删除。新包放到目标后保存新登记；两者完成才刷盘 Committed。成功后只清理本次事务，不清理其他模块或历史发布 ZIP。

失败或下次启动遇到 Prepared：校验整份记录、路径边界、链接、文件归属与登记冲突后，恢复本次操作前的目标包和登记。恢复使用复制，不提前消耗唯一备份；重复恢复应幂等。恢复也失败则保留全部证据，禁止继续模块变更或加载不确定状态，给出明确诊断。Committed/RolledBack 只收尾，不回退已经成功的版本。

这不是根据服务器或运行结果自动降级模块；只恢复尚未完成的安装操作。主程序/模块版本回退仍需用户主动确认。主程序替换前的共享兼容门禁也拒绝未完成的模块事务和不明确的资料，避免绕过模块错误。

### 3. 诊断反映实际状态

登记文件整体错误必须出现在每个相关游戏的报告，不能被模块 ID 筛选掉。模块清单缺失、身份/版本不符、不安全程序集路径、DLL 缺失等分支记录具体原因，不静默跳过。一个模块的错误不串到另一个模块；全局资料错误则保留。

未安装为“信息/尚未检查”，已登记但未加载为失败，只有确实加载了适配器才报告加载通过。目录服务的资料/事务错误一起进入报告，并继续使用现有脱敏逻辑。损坏时 UI 显示“资料无法安全读取”，不显示成“未安装”；变更按钮关闭，诊断保持可用。

### 4. 同一数据目录单实例

主程序启动入口在待更新处理、资料加载及临时清理之前取得数据目录专属跨进程文件租约，持有至退出。第二实例不能执行上述动作；在校验 PID 与进程启动时间后尝试恢复/前置已有窗口，否则给出简短提示并退出。不同独立数据目录可分别运行。

文件留存不代表被锁，进程退出或崩溃会由系统释放句柄，下一次启动无需删除锁文件。权限等非占用错误不能当作已有实例，也不能绕过租约继续启动。既有游戏库写锁保持不变，单个主程序仍支持多个游戏会话。
