# v0.3.0-preview.14 版本信息与模块小版本兼容方案

## 目标

1. “游戏版本”页分开显示游戏平台版本、游戏自身声明版本与引擎文件版本。
2. 游戏安装目录移动后继续按运行进程连接并刷新路径，不把目录当作模块兼容身份。
3. 模块目录按游戏身份发现可下载包，模块本地代码负责最终安全兼容判断。
4. WorldApart v1.1.0 支持已验证的新构建，并为布局未变的小版本提供严格结构签名回退。
5. 右下角更新按钮显示在检测出的版本/状态文字左侧。
6. “游戏版本”页在内容超过可用高度时启用纵向滚动，较小窗口也能访问底部信息与本地数据按钮。

## 开工前的三轮审查

### 安全审查

- 不允许因为 EXE 相同或版本号相近就复用旧 RVA。
- WorldApart 新旧构建使用独立 `BuildLayout`；结构回退同时核对读取、写入、保存、主线程钩子与版本读取等全部关键函数签名。
- 写入前仍校验主线程入口完整机器码，写入后仍走游戏保存与回读。

### 架构审查

- 平台清单解析独立为 `GameVersionMetadataService`，不继续堆进 `MainViewModel`。
- 可选的游戏自报版本通过 Host API `IGameVersionMetadataProvider` 获取；不强迫所有模块实现。
- 服务器目录“发现模块”与本地模块“能否启用”分离，避免目录兼容规则与内存安全规则互相污染。

### 交互与发布审查

- 新构建未被目录精确登记时，允许下载安装，但明确显示“安装后本地安全验证”。
- 版本页用“未提供/未识别”表示确实没有数据，不伪造版本。
- 模块先完成实机同值写入、回读和版本读取验证；随后发布模块与目录，再发布主程序；完整离线包只生成在本地，不上传 GitHub。

## 验收证据

- 主程序烟雾测试覆盖 Steam manifest 匹配、库 schema v7、非精确构建的模块发现与更新状态恢复。
- WorldApart 当前构建实机通过：背包同值写入、人物属性同值写入、游戏自动保存回读及 Unity `Application` 自报版本读取。
- 标准包、模块包与完整离线包均需执行 ZIP 内容、SHA-256 和启动验证。
