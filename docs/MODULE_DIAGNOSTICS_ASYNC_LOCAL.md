# 专属模块诊断后台化（本地实现）

## 范围与问题

主程序的“诊断”原来在 WPF 点击事件内同步生成报告。报告调用模块的 `Supports`、旧页面能力检查和扩展诊断；这些只读回调可能等待游戏线程、读取元数据，因而使整个窗口失去响应。本轮仅修复宿主执行与结果交付，不修改任何游戏模块、识别规则、Host API、概率/材料算法或存档。

用户授权仅本地代码实现：不升版本、不打包、不提交、不发布。

以上为 2026-10-13 原实现阶段的授权范围。2026-10-15 用户另行授权提交和发布全部当前改动，正式集成及验证见 [v0.5.5 发布方案](RELEASE_0_5_5_PLAN.md)；下文保留本地实现时的历史记录。

## 详细方案

1. 点击事件改为异步入口。UI 线程先捕获所选游戏、版本、进程、构建、会话与模块实例；版本报告字段、加载错误和资料错误复制成快照，后台不遍历 UI 集合。
2. 复用注册器已有的兼容检查串行门禁，把报告生成及所有模块只读回调放到后台。连接检查与诊断不并发进入 `Supports`，不新增游戏特定逻辑。
3. 仅诊断按钮在当前诊断期间不可重复点击，其它控制与游戏切换不被诊断锁住。不得为重复点击或切换自动创建重试任务。
4. 切换游戏/版本、连接变化及正式关闭时取消诊断。取消只在排队及回调之间生效；已经进入的同步模块回调自然结束，不终止线程，不提前释放其资源或串行门禁。
5. UI 线程续接后核对操作代、对象引用、模块 ID 与原适配器是否仍在注册器中。同一个游戏 A→B→A 也丢弃旧报告；模块停用、替换及关闭后的结果或异常不弹到新页面。
6. 通过同步 UI 回调立即展示已核对的报告，避免“任务返回后、弹框前”再次异步调度产生归属竞态。报告文字、脱敏及模块异常变为失败项的规则不变。
7. 退出不等待诊断任务，取消仅发生在退出准备成功、正式关闭已提交之后；原有退出准备失败时的恢复行为保持不变。

## 编码前检查三遍

- 第一遍：需求与边界。确认唯一生产入口是主窗口诊断按钮；保留未安装/损坏模块的基础诊断，保持只读、不联网、不要求新启动参数。
- 第二遍：线程与竞态。确认后台服务不创建页面；不读取可变的版本/错误集合；复用兼容门禁；重复点击、A→B→A、模块替换和迟到异常均有明确处理。
- 第三遍：生命周期与影响。取消不冒充终止同步原生调用，门禁保持到真实回调结束；取消发生在正式关闭提交之后；不修改 SDK、模块算法或版本发布资料。

上述三遍已在编码前核对通过。

## 验证计划

新增隔离的 STA/WPF 回归：阻塞模拟回调期间 UI Dispatcher 可继续工作；回调线程不是 UI；重复点击不产生第二个回调；切换游戏/版本/进程、A→B→A、模块停用/替换与关闭不展示旧结果；排队取消不调用模块；在同步回调结束前不释放门禁；异常隔离、快照及完成后按钮恢复。

随后执行宿主 Release 构建、完整冒烟回归，并分别检查生产调用链、并发/生命周期和最终差异。只使用测试夹具，不操作真实游戏或存档。

## 编码后检查与结果

2026-10-13 完成本地实现及三遍复核：

1. 生产路径复核：主窗口唯一入口已改为异步；报告服务的 `Supports`、旧页面能力检查及扩展诊断均在后台；不创建页面，不调用字段写入或保存；已有报告内容和脱敏规则不变。
2. 并发与生命周期复核：排队前取消、同步回调中取消、扩展诊断中取消均覆盖；重复点击不重复执行；A→B→A、版本/进程/构建/会话变更、模块 ID 变更、停用/替换、迟到异常和正式关闭不交付旧结果。取消后门禁保留到真实回调结束。退出准备失败仍可完成原诊断。后台读取前先阻塞门禁，再改变 UI 元数据，证实报告使用原快照。
3. 集成与差异复核：宿主完整冒烟通过，包括原有游戏识别、页面缓存、字段操作、下载、布局和退出回归；差异只涉及宿主诊断、回归和文档。模块仓库无改动，SDK、版本号及发布资料不变。
