# v0.5.1 集成发布方案与复核

## 范围与方向

用户本轮确认游戏库图标调整，并授权完成后提交、发布；包含此前明确授权、暂留本地的后台操作、字段顺序、共享目标协调、解锁和刷新边界修复。不新增游戏功能，不改变页面分类，不操作真实游戏数值，不覆盖旧版发行包。

游戏专属页面仍由模块自由实现，宿主仅统一主题、身份、安全边界与字段协调。主程序与模块版本独立递增；兼容关系由协议和版本范围声明，不要求版本编号相等。

## 详细实施

1. 游戏库单行顺序为头像、名称、置顶、锁定、已加载本地模块、已连接。前三个图标槽仍固定为 24 DIP，连接槽 32 DIP；未生效时 Hidden，不让其它图标占位。置顶和已加载图形为 14×16 DIP，锁定 13×15 DIP，连接仍 24×28 DIP；头像、透明遮罩裁剪、主题动态色、悬停及无障碍名称不变。
2. 将布局回归按实际状态语义映射，不能因置顶/锁定交换顺序而把显示绑定测试也交换错。覆盖五套主题、三种宽度、长名称、全部 16 种状态组合和固定按钮间距，生成真实 WPF 渲染供目视检查。
3. 合入已批准的本地修复：取消/解锁/切换后丢弃迟到操作；同一保存条目串行；按实际目标协调模块页、快捷入口、扫描和锁定；停用/无法连接时仍能解锁；快照读取遇协调写入、页面失效或模块停用时丢弃旧数据和旧错误，不自动重试。
4. 主程序和更新器升为 0.5.1，SDK 两仓副本升为 4.0.3（CLR AssemblyVersion 保持 2.0.0.0），Host API 8 正式化，资料 Schema 7 和目录 Schema 5 不变。三个修改模块分别升为 WorldApart 1.3.4、Fzzml 2.1.4、Last Epoch 0.5.5，最低主程序版本均为 0.5.1。稳定 ID、编辑器语义键、已验证游戏构建指纹不变。
5. 同步实际打包能力声明、发布索引默认上限和相应回归，确保标准包不会错误声明仅支持 API 7。旧 API 6/7 页面仍可加载，但未桥接的模块字段锁定暂停；主程序回退到 API 7 版本前必须手动回退 API 8 模块，绝不自动回退。
6. 同步 README、架构、扩展规范和发布说明。历史 *_LOCAL.md 记录保留当时未发布的事实，新增本次集成说明，不改写历史验收为当时已发布。

## 提交前与发布步骤

1. 三遍实施后检查：布局与显示契约；操作生命周期/兼容性及真实编译模块页面；全量构建、回归、编码/链接和差异检查。以实际执行结果为验收，游戏内效果不在本轮承诺中。
2. 检查并提交两个仓库的已批准差异。正式包从干净提交重建，二进制 ProductVersion 跟踪源码提交；主程序标准包做启动和更新器测试，模块 ZIP 仅含 DLL 和 module.json。
3. 先发布主程序 0.5.1，通过现有代理和幂等上传器上传标准 ZIP，再独立校验 GitHub 大小/摘要；更新并推送索引、读回公开文件。再发布三个模块的不可变包，全部远端核验后才更新、提交、推送目录并读回。
4. 目录和索引各保留最新 3 个快照，确认它们指向已验证资产后清理第 4 个旧 Release/资产，保留 Git 标签和源码历史。网络失败仅重试失败步骤，不重复启动上传。
5. 用已验证标准包和模块目录生成本地完整离线包，实际加载三模块并创建页面、核验原哈希、隔离启动、保存外部 receipt。运行离线组合与真实核验器回归；完整离线包不上传 GitHub。
6. 最后核对远端分支、标签、公开索引/目录、四组各 3 个 Release 和两个仓库干净状态，交付链接及 SHA-256 证据。

## 实施前检查记录

1. 视觉契约：核对实际 XAML、透明遮罩和 16 状态测试；交换列而非状态含义，固定槽不缩小，连接/头像不改，五套主题与按钮布局保留。
2. 安全和兼容：核对 SDK 新能力、旧页降级、真实模块清单/项目。发现 API 8 源码仍声明旧最低宿主版本；本次改为真实首个 API 8 主程序 0.5.1，并递增各独立版本，不改变游戏指纹或稳定身份。
3. 发布/回退：已用只读保留计划验证远端目前主程序及各模块均保留三包，最新标签分别是 0.5.0、1.3.3、2.1.3、0.5.4。发现打包能力和索引默认上限仍为 7，纳入修复及回归；模块包不能在脏树正式构建，实施前验证使用明确的隔离源码夹具，最终资产从干净提交生成。先主程序再模块目录，全部远端验证后才清理第四个旧包，保留标签；历史夹具版本不机械改写。

## 实施后验收

1. 第一遍（布局）：完整 Release 构建零警告、零错误。布局回归覆盖五主题×三宽度、长名称及 16 种状态组合，前三槽 24 DIP、连接槽 32 DIP 不变，图形尺寸和置顶/锁定状态映射正确；本游专属 8 DIP、页脚 12 DIP 间距保持。生成 30 张真实 WPF 离屏渲染，目视检查浅色 1320 与深色 1080，缩小后的图形和名称比例、固定位置正常。
2. 第二遍（生命周期/兼容）：全量冒烟在新 API 8 隔离源码夹具和既有 API 7 原 ZIP 上各通过一次，新旧各三个模块创建 2/2/5 共九页。主要回归断言：模块/实例 163、安全边界 207、游戏生命周期 89、后台操作 112、字段/页面 109、刷新/解锁 144、共享目标 115、扫描读取 65；稳定性、下载反馈、布局、关闭、编解码和指纹也通过。模块 SDK、三个游戏和实机测试项目编译零警告/错误，真实编译页面读写/快照回归 180 项通过。两仓 SDK 契约和项目文件 SHA-256 相同，清单/主题所有权验证通过，游戏身份/构建内容没有变化。
3. 第三遍（交付/差异）：应用打包失败/不可变边界 13 项、离线组合 80 项、双方保留策略模拟通过。独立未发布 review 包已真实启动并通过更新器沙盒（文件锁、恢复、强制中断、执行时兼容、旧版升级与不安全记录拒绝）；它不能代替从干净提交重建的正式包。66 个修改/新增文本通过严格 UTF-8、冲突/空白检查及 68 个本地文档链接核验；修改的 PowerShell 脚本语法、两仓 git diff --check 通过，已检查队列取消释放和原 Dispatcher 原子快照应用。首次无显式代理的 host fetch 被重置，显式代理重试成功，两个仓库均与远端无分叉；旧 v0.5.0 公开资产大小/摘要独立核验一致。没有遗留 rg 扫描进程，没有连接/修改真实游戏。

以上完成提交前三遍检查。最终标准/模块 ZIP、公开摘要、索引/目录、三包清理及完整离线包的结果在提交后按同一流程核验并追加记录，不提前把计划当成已发布。
