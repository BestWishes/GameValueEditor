# 本地可靠性改进设计（2026-10-06）

发布状态：这些修复纳入 v0.5.0，见[集成复核与发布记录](RELEASE_0_5_0_INTEGRATION_REVIEW.md)。下文保留原本地实施的授权范围、旧版本产物与检查证据，不代表后续用户授权的发布状态；旧资产不覆盖。

## 范围与边界

本轮仅修改本地，不提交、推送、打标签或上传，不递增版本。不覆盖已经发布的 0.4.9 标准包及完整离线包。模块仓库、游戏适配数据、游戏内存与存档均不修改。保留上一轮离线打包工具及文档的未提交改动。

## 详细方案

1. **标准包事务化生成**：保留正式发布的干净工作树、版本递增和源码提交检查。构建使用独立 GUID 工作目录；从明确的六个文件创建临时 ZIP；检查文件集合、主程序/更新器版本与源码提交，执行启动及更新器测试，全部通过才原子移动到目标。相同版本已有包不覆盖；构建失败不删除任何旧标准包或离线包。旧包清理由发布保留策略处理，不由构建预先删除。新增可注入构建/验证函数的隔离回归测试。当前代码通过独立的本地 review 目录验证，不走正式发布入口。
2. **离线完整性与新旧程度分离**：成功核验的 ZIP 在 `artifacts/offline-bundle-receipts/<SHA256>.json` 保存本地核验记录，冻结宿主来源、模块身份和每个文件的散列；记录在 ZIP 外，不改变原包。`VerifyOnly` 优先按记录验证原始文件图，不依赖当前最新模块或原模块 ZIP。无记录时按包内已安装版本查找保留目录和原始 ZIP，不能拿最新版作为完整性标准；证据缺失明确报“缺少核验证据”，而非“包损坏”。目录的新版本仅影响单独的新旧状态，目录不可用则新旧状态未知。记录是本机可信工作流的证据，不宣称数字签名或抵抗本机文件被同时篡改。
3. **真实模块与页面核验**：为冒烟测试增加独立快速模式，在隔离目录加载离线包内实际 DLL，检查加载错误、模块身份/版本、编辑器注册和每个模块自有 WPF 页面创建与释放。输出结构化记录，主程序语义版本必须相符；保留真实打包 EXE 的启动测试。页面核验使用当前构建的宿主实现，不能声称证明历史宿主二进制的全部行为。没有连接游戏，不调用任何写入或保存操作。生产打包没有跳过此核验的开关。
4. **下载反馈与取消**：保留总超时 20 分钟、连续无数据 60 秒和失败清理临时下载。增加连接、等待数据、速率以及校验/安装阶段反馈；等待期间定期刷新状态。主程序更新/回退和模块安装/回退共用单个可取消下载会话，避免状态互相覆盖。取消仅在网络传输阶段可用；进入散列校验/安装前同步关闭取消窗口，安装事务不被 UI 中断。取消不作为错误弹窗、不生成待更新记录、不触发重启提示，不改变已安装版本。迟到进度回调不能覆盖操作结束状态。退出应用时只取消仍可取消的传输。
5. **固定布局与文案**：底部新增固定宽度的取消槽位，空闲时 Hidden 而非 Collapsed；既有回退/查新/更新/官网四按钮位置、间距、主题样式保持不变。诊断提示剩余“检查新有”改为“查新”。

## 写代码前的三遍检查

### 第一遍：需求与方向

取消是用户主动操作，不是自动回退或自动重试；主程序和模块版本独立，兼容范围不变。完整性与是否最新是两个结论。构建不删除旧包，满足失败后仍有可用包的目标。新增反馈不改变已批准的图标、按钮顺序和固定位置。

### 第二遍：状态与失败边界

核验、启动、原子移动任一步失败保留原包；临时资源只清理本次创建的受限目录。核验记录不能从待验证 ZIP 自行生成后就作为可信证据。下载取消与阶段切换通过同步状态门隔离； UI 派发的进度不得延长取消窗口。取消、超时、网络错误分别处理，模块安装/更新器待更新事务保持现有语义。

### 第三遍：可验证性与交付

隔离脚本测试覆盖构建失败、核验失败、目标占用、已有包；离线测试覆盖旧模块仍完整、目录不可用、无源 ZIP、记录/文件被篡改及模块核验失败。C# 测试覆盖下载取消、等待、速率、超时、状态复位与固定布局；运行完整 Release 构建/冒烟测试及实际三个模块九个页面核验。单独生成未发布的本地 review 包验证启动与更新器。交付前复核旧包 SHA、两个仓库 HEAD/状态、文档和差异空白检查。测试不等于真实游戏效果验证。
