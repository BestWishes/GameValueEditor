# v0.3.0 正式版收尾方案

## 目标

- 自 `v0.3.0` 起只发布三段式正式版本，不再维护预览版更新通道。
- 将通用实体编辑契约标记为 Host API 3，阻止旧宿主误载依赖新契约的模块。
- 更新安装时从已校验的目标 ZIP 提取新版更新器，不再使用安装目录中的旧更新器执行升级。
- 发布、测试与模块校验不依赖 GitHub Actions；账户账单状态不得阻断本地验证和 GitHub Release API 发布。
- 主程序与每个游戏模块在 GitHub 上只保留各自最新的正式 Release、标签和下载资产。

## 实施顺序

1. 固定主程序 `v0.3.0` 和 Host API 3 契约，保留 API 2 模块的程序集绑定兼容。
2. 让 Last Epoch 以新模块版本声明 Host API 3；其余未使用新接口的模块继续声明 API 2。
3. 完成正式版更新筛选、新更新器引导、缓存清理和人工恢复入口。
4. 删除失效的 GitHub Actions 工作流，增加本地一键验证脚本。
5. 先发布并验证模块资产，再更新公开模块目录；最后发布主程序正式版。
6. 校验公开下载 SHA-256 后删除被替代的旧 Release 和标签。

## 验收条件

- 正式版本解析拒绝带后缀版本；更新检查忽略 GitHub prerelease 和模块 Release。
- API 2 的现有模块仍可由新宿主加载，API 3 模块会被旧宿主明确拒绝。
- 更新启动器来自目标 ZIP，ZIP 哈希变化、更新器缺失或重复时安全失败。
- 更新目录只保留当前待安装包和最新诊断，旧 runner、解压目录、失败清单和旧版本包会被清理。
- 主程序完整验证、模块完整构建与目录校验全部通过。
- 线上只保留最新正式主程序包，以及每个模块各自最新的正式包。
