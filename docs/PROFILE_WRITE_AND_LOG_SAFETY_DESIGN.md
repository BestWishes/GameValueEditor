## 1. 游戏库必要结构校验

在反序列化前检查原始 JSON，避免模型的默认空集合把缺失字段补成正常空库。

- 根节点必须是对象，必须显式提供数组 `Games`。每个游戏必须是对象并显式提供数组 `Versions`；每个版本必须是对象并显式提供数组 `Fields`；字段必须是对象。合法的空数组保留合法性。
- 按现有大小写不敏感规则识别属性；对象内同名（含大小写差异）属性拒绝，防止两个集合/格式声明产生歧义。其他新增/未知属性不一律拒绝，保持可扩展性。
- 显式 `SchemaVersion` 必须是 1–7 的整数；未来格式直接拒绝，不用旧备份掩盖或覆盖。没有格式声明但具备完整必要集合的旧资料按旧格式读取，再按既有规则迁移至 7；缺少可选新字段仍可用默认值。历史保存的列表结构须在设计检查中核对。
- 主文件结构损坏时读取有效备份；恢复后保存仍不能把损坏主文件覆盖到有效备份。双份损坏时保留现场并拒绝保存。仅主文件和备份都不存在才创建新空库。
- 保存仍先取得独立快照，使用既有信号量、跨进程锁、刷盘与原子替换；不引入另一套存储机制。

验收：`{}`、缺列表/列表 null/非数组、非对象项、重复属性、非法/未来格式；有效空库、大小写兼容、格式 1–7/无格式旧资料、可选字段缺省、坏主文件与好备份、双坏文件及保存不覆盖证据。

## 2. 通用写入与回读分层

新增宿主内部、可测试的共用写入结果：写入失败、写入完成但回读失败、写入完成但回读不一致、写入完成且回读一致。按已经编码的目标字节做一次写入和一次完整回读，不增加延迟、循环尝试、自动还原或游戏专属推断。

- 手动扫描候选/批量修改：未知结果不得显示目标值代替实际值；回读失败显示未知，回读不一致显示实际值。批量结果分别计数四类，部分失败不声称全部成功；保留有限具体错误并提示在游戏内确认效果。
- 已保存的通用字段：实际回读值进入界面，回读失败显示未知；只有实际读到完整值才更新 `LastVerifiedUtc`。写入失败不更新进程/定位验证记录。警告不能被外层“字段已更新”文案覆盖。
- 原来启用数值锁定的字段，如果这次手动写入完成但回读失败/不一致，暂停该字段锁定并明确说明，避免把未知结果作为新的锁定目标，也避免旧锁定目标继续覆盖这次操作。回读一致时才更新锁定目标；写入失败不宣称已改动目标。
- 既有周期锁定仍按用户主动启用的机制运行，不新增重试频率。其写入也使用共用回读结果，不把预期字节当作真实当前值；取消后的迟到刷新不能重新覆盖界面状态。
- 模块自身的语义读写、保存及真实玩法验证保持原契约，不用普通内存回读去证明模块属性已经生效。

生产进程访问器仍校验 PID/启动时间、扫描代与构建身份；仅增加宿主内部写入访问接口供故障测试替换，不开放新的公共 SDK 能力。候选列表与按钮布局不变，不新增状态列。

验收：四种结果、短回读、批量混合计数、未知值不伪造、类型/比例编码与字节比较、保存字段警告不被覆盖、验证时间、锁定目标/暂停、取消刷新；自有缓冲区实际写入回读和拒绝错误进程/扫描代/构建。

## 3. 错误日志兜底与限量轮换

错误日志服务不得把可处理的日志失败再次抛给异常处理入口。

- 正常位置保持 `data/crash.log`，另保留 `crash.1.log`、`crash.2.log`，每份最多 1 MiB；单条日志也限长并注明截断。已存在的超大日志只保留末尾有界内容，不能把整份大文件搬成无限大的备份。
- 正常目录不可写、文件锁/权限/磁盘等失败时，尝试专用临时目录。临时目录按程序数据目录身份隔离，避免不同安装互相覆盖日志；同样执行三份限量规则。
- 两处都失败时返回“未记录”，原异常仍显示，不能声称日志已写入或提供不存在的成功路径。格式化异常详情本身失败也有简短兜底。
- 同服务并发写入串行化；只轮换上述明确归属的文件，不递归扫描/删除数据目录。超大日志裁剪使用同目录临时文件、刷盘后替换；失败不主动删除原文件。符号链接日志路径拒绝写入并尝试兜底。
- UI 异常入口先标记已处理，再尝试日志和原错误提示；更新恢复启动分支不因日志失败绕过原来的停止启动保护。日志只留本机，不自动上传，不扩展为诊断收集功能。

验收：正常写入、多线程、轮换数量/容量、单条超长/中文边界、原超大文件、主目录不存在/不可写/日志锁定、临时目录也失败、格式化失败及原异常信息保留；不得留下测试文件或日志写入临时文件。
