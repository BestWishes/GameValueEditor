# 公共窗口误识别与本地资源清理工具（2026-10-12，本地）

后续用户授权提交、发布，集成至主程序 v0.5.4，四个模块不变。用户要求先查看清理清单再决定是否删除，因此正式发布阶段也不清理真实本地 ZIP 或远端旧 Release；以下保留此前本地实现/测试时的实际授权与证据。正式交付与发布后预览见 [0.5.4 记录](RELEASE_0_5_4_PLAN.md)。

## 现象和范围

用户实际运行完整包 `GameValueEditor-v0.5.3-202610122` 时，库内连接最后纪元打开关联窗口。只读核查发现实际 `Last Epoch.exe` 之外，`steamwebhelper.exe` 的 Steam 详情窗口标题为“最后纪元”，生产名称解析将两者都认作候选；真实游戏的构建读取、名称解析均成功。此问题不是新模块的离线模式检查或文件哈希变化导致。已确认主程序 v0.5.2、v0.5.3 标签含同一规则。

本轮获准修复宿主、制作本地离线包及可重复清理工具，不提交、推送或发布，不改游戏文件、存档和用户正在运行的目录。实际 dist 删除此前被执行策略拦截，不通过新工具重试该操作；只预览真实目录，在独立小型夹具中测试删除。

## 详细方案

1. 名称匹配仍为首要身份规则。用户可编辑的 `GameProfile.Name` 只作备注显示，不参与身份和模块归属匹配；使用原进程名、产品名、游戏实际声明名称及模块明确别名。为共用运行程序且无产品名的游戏，首次连接采集真实根窗口名称至可选 `Identity.GameName`，重命名不修改该字段，后续连接不替换已采集的原始名称。旧数据不把备注当成可信原名；已存进程/产品名及模块别名继续可用。模块 ID 仅用于包管理和取出模块声明，不作为进程归属证据。复用宿主已有的公共启动器/浏览器分类，公共程序的窗口标题不代表正在运行的游戏。通用 Electron/NW.js 游戏不被当成浏览器排除；不加入游戏名称、Steam App ID、指纹白名单等特例。
2. 覆盖 Steam 同名详情页、浏览器和资源管理器同名窗口、只有公共窗口、普通未知游戏、小版本哈希变化、两个真实实例、共用引擎游戏窗口等情况。真实 Last Epoch 只读生产候选发现必须只得到实际游戏进程；不连接或写入游戏来验证识别。
3. 新建 `clean-local-artifacts.ps1`，默认仅生成清理预览，显式 `-Apply` 才删除。只枚举宿主 dist 根目录 ZIP 以及两个明确的旧工具子目录，不递归探索任意目录。可显式包含模块仓库 dist，但默认不扩展删除范围。
4. 标准主程序包保护发布索引中所有保留记录（正常为最近 3 版），并核对存在文件的大小和 SHA-256；预备发布、未知版本或无索引证据的包不会当成历史包删除。离线包以外部核验记录和完整 ZIP 内容核对归类，保留最近 3 个不同内容，按版本和文件生成时间排序；最新完整包优先占用一个保留名额，其余名额选最新的完整/指定模块包，避免子集包挤掉唯一完整包。内容相同的别名仅保留一个，不重复占名额。未知/缺失核验记录的包保留并说明。旧命名格式仅识别既有工具产物，不扩大到任意 ZIP。
5. 可选模块清理以当前目录保留的快照 ZIP 为保护集，各模块最近 3 版由既有目录维护，工具不重新发明服务端保留规则。未知或待发布版本保留。所有删除项先冻结大小、时间、散列，删除前重新计算方案和验证全部目标；拒绝路径越界、重解析点、目标变化。保留 receipts、源码、非 ZIP、目录、个人数据。
6. 模块离线核验集成测试改为可指定 `-BundlePath`，默认选有核验记录的最近完整包，不再固定要求 `complete-offline-win-x64.zip` 旧别名。打包不自动运行清理。公开预览/应用/WhatIf 命令和安全边界。
7. 构建、专项/完整回归、隔离清理夹具、真实目录预览、实际四模块及新包验证分开记录。新包使用独立 local-review 主程序输入，不覆盖已发布 0.5.3 标准资产，也不伪装为正式新版本。

## 编码前复核（三遍）

- 第一遍，需求与方向：名称识别不回退为哈希授权；公共窗口不是第二个游戏实例；宿主不加入游戏专用分支，模块版本/API 不变。
- 第二遍，边界与时序：保留真实多实例选择；多个候选不按内存猜测。清理仅有限目录，所有候选在删除前核验，未知文件和将来版本默认保留，不自动加入发布钩子。
- 第三遍，交付与依赖：正式标准包、目录模块输入、外部记录保留；先解除集成测试对旧包别名的固定依赖；清理工具默认预览，实际删除拦截不会被包装脚本绕过。新主程序只交本地 review 完整包。

用户进一步明确名称必须与可编辑备注分离后，追加三遍复核：名称来源不从备注迁移；普通游戏首次采集/重命名/重新连接/保存失败回滚均保持识别名称；旧档案可通过既存进程名、产品名和模块别名识别，不使用猜测备注补数据。采集名称的可选字段不改变 Host API 或库 Schema。
