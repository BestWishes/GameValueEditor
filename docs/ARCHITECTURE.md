# 架构说明

## 产品边界

肝肾大圣是面向 Windows x64 离线单机游戏的本地扫描器和模块宿主。扫描结果属于临时会话；玩家确认的游戏、构建和字段属于便携式本地档案。项目不提供在线游戏支持、反反作弊、驱动或隐藏行为。

## 仓库职责

主程序仓库负责：

- 进程发现、逻辑进程组、构建指纹、内存扫描和游戏加速。
- 游戏库、快捷入口、锁定、主题、弹框、模块安装和应用更新。
- 游戏内页面的导航容器、主题、生命周期和通用弹框/保存字段服务。
- `GameValueEditor.ModuleSdk` Host API，以及模块加载、影子隔离、安全校验和通用兼容性诊断界面。

独立的 `GameValueEditor-Modules` 仓库负责：

- 每个游戏的稳定模块 ID、进程身份和兼容构建。
- 页面清单、稳定编辑器 ID、显示名称、顺序、字段生命周期，以及完整 WPF 页面、页面状态和交互。
- 游戏运行时定位、线程切换、刷新、保存、真实回读，以及可选的游戏专属只读诊断项。
- 游戏专属文档、实机测试、贡献者和发布资产。

普通新增游戏不得要求主程序增加游戏 ID、页面名称、固定 Tab、编辑器后缀判断或游戏专属测试分支。模块可以为每个游戏自由设计页面；跨模块复用控件是模块仓库自己的选择，不进入宿主页面协议。

## 固定操作栏与模块标记

宿主游戏库用嵌入的原始 PNG 透明轮廓和动态 AccentBrush 标记已安装模块；渲染 Viewbox 排除大面积透明留白，图标不代表实际构建已兼容。模块操作栏和页脚分别使用局部固定宽度按钮，实际边缘间距均为 8 DIP，不继承全局按钮额外 Margin。查新、更新为独立状态及事件；版本、进度、后验证提示放状态区或 ToolTip，不改变操作按钮坐标。具体契约与回归见 [固定布局设计](STABLE_MODULE_AND_UPDATE_ACTION_LAYOUT_DESIGN.md)。

## 持久数据

```text
LibraryDocument
└─ GameProfile
   └─ GameVersionProfile
      └─ SavedField
```

- `GameProfile` 保存玩家看到的游戏条目、安装路径、置顶、锁定和可选模块 ID。
- `GameVersionProfile` 保存确定构建；普通游戏使用 EXE SHA-256，IL2CPP 游戏还组合 `GameAssembly.dll` 与 metadata。
- `SavedField` 保存玩家备注、分组、类型、定位器和模块语义键；显示名称从不作为内部身份。

原始地址不能跨进程或构建复用。可迁移的专属字段只能使用模块、编辑器、实体和字段组成的稳定语义键。

`ProfileStore.SaveAsync` 在调用线程取得独立序列化快照，再通过路径级信号量和跨进程文件锁串行写入。唯一临时文件刷盘后原子替换；损坏的主文件不能覆盖有效备份。缺主文件仍读取备份；双份损坏或未来 Schema 保留原资料并明确失败。

## 进程与扫描

`ProcessService` 把同一实例的父子进程归成逻辑游戏组，并根据窗口、运行时和工作集选择实际数据进程。数据进程重建时，宿主销毁进程级服务和临时地址，但保留可重新定位的语义字段。

首次扫描完整遍历可读内存并把候选写入 `data/scan-temp` 分区；界面只物化有限预览，再次扫描仍过滤完整候选集。清空、断开、进程重建和正常退出都会清理对应临时目录。

异步游戏操作捕获游戏、版本、连接实例、会话与单调递增的操作代。切换 A→B→A 仍使原响应失效；旧扫描结果与错误被丢弃，全局忙状态由发起任务释放。候选带扫描代 ID，扫描源与实际打开的进程句柄核对 PID/创建时间。过滤排队前取得源读租约，取消/清理不删除仍在读取的分区。Int64 编码使用精确有理数与整数范围校验，增加/减少比较使用实际整数类型，不经过 double。

## Host API 7

公共契约位于 `src/GameValueEditor.ModuleSdk`。CLR `AssemblyVersion` 保持兼容绑定，实际能力门槛由 `module.json.hostApiVersion` 控制。

- `IGameAdapter`：模块身份、构建支持、编辑器描述和语义字段读写。
- `IInventoryGameAdapter`：集合/背包页面能力。
- `ICharacterAttributesGameAdapter`：人物属性页面能力。
- `IEntityEditorsGameAdapter`：装备、资源、进度等实体数字字段能力。
- `IGameEditorPageProvider`：仅供 API 4/5 旧包兼容，把编辑器绑定到旧标准页面角色。
- `IGameEditorPageFactoryProvider`：API 6 起必需，模块按编辑器 ID 创建完整 `IGameEditorPage` WPF 页面。
- `IGameEditorHostServices`：向模块页面提供通用输入、错误提示、状态和保存语义字段流程，不暴露宿主内部类型。
- `ModuleVisualResources`：API 7 提供稳定的主题资源键与间距常量；模块自由组织视觉树，但不能自定义主题颜色、全局字体或独立窗口外壳。
- `IGameCompatibilityDiagnosticsProvider`：API 5 必需，返回只读、可脱敏展示的游戏专属兼容检查结果。
- `IGameEditorFieldPolicyProvider`：可选，声明混合页面中单个字段的持久化和锁定策略。
- `IGameVersionMetadataProvider`：可选，只提供游戏自报版本信息，不能代替构建验证。

宿主加载模块时核对程序集与 `module.json` 的模块显示名，以及编辑器 ID、名称、顺序和生命周期。API 4/5 要求旧角色注册与编辑器一一对应；API 5 起要求兼容性诊断；API 6 清单删除 `kind`，并要求模块页面工厂为每个编辑器创建真实页面；API 7 正式定义宿主视觉资源契约。宿主不读取模块页面内部控件，也不按类型或编辑器 ID 选择布局模板。

“兼容性诊断”由宿主统一生成基础报告，不依赖服务器目录或已安装模块才可打开。模块扩展诊断只能读取进程和构建状态，不得写内存、调用保存流程或返回本机路径、PID、内存地址、存档内容；宿主会再次脱敏，并把提供器异常隔离为失败项。

自有页面工厂仅证明页面已注册，宿主报告为 Information，不假定所有页面兼容。模块只读诊断应分别说明各页面前置条件和构建支持；不为诊断执行页面读写。

## 模块安装与隔离

模块目录先按进程名发现可下载模块；下载安装后仍由模块的 `Supports` 对当前构建执行精确指纹或完整结构验证。未知布局必须安全拒绝。

ZIP 先校验大小、SHA-256、清单身份、Host API、最低/最高主程序版本和路径，再解压到 `data/modules/packages/{模块ID}/{版本}`。运行时从会话影子副本加载，因此安装源包可更新或卸载。API 2–5 的无 UI 加载上下文可回收；WPF 会缓存页面类型/资源，API 6 及以上 UI 上下文按进程期保留。替换这类模块后只停用目标模块、取消并释放页面，等待用户重启后加载目标版本，不能在同一进程并存新旧 WPF 程序集。

模块与游戏库保持一一关联。卸载模块保留普通游戏档案；从库移出会先卸载模块，再删除档案。模块贡献者来自包内快照，宿主只负责展示。

模块检查结果绑定发起时的游戏、版本、连接、构建指纹、会话及页面代数。切换后旧响应和失败不会写入当前页面；按钮和实际安装/回退命令都核对上下文。下载仍针对原模块完成登记，进度明确标注模块名称。加载器以进程期 ID 集合约束待重启模块，任何重载、卸载其他模块或同进程重装都不能绕过停用；未受影响的适配器实例继续复用。

## 更新与发布

应用只接受正式 `A.B.C` 十进制计数器版本，`B/C` 为单个数字；每次正式发布只加 `0.0.1` 并自动进位。主程序和每个模块分别按自己的正式标签递增，编号无需相等；模块每个版本通过 Host API 与最低/最高主程序版本建立显式兼容关系。服务器分别只保留主程序最近 3 个正式 Release 和每个模块最近 3 个正式 Release，清理资产但保留 Git 标签。主程序与模块都只提供用户确认后的手动回退，检查或失败不会自动降级。独立更新器校验大小与 SHA-256、拒绝越出应用目录的路径、跳过 `data`，并在文件替换失败时恢复本次事务前的原文件。

GitHub Actions 不是发布前提。正式发布必须先提交源码并保持干净工作树，再从该提交构建最终资产；二进制 `ProductVersion` 中的源码提交号、带注释标签和远端分支必须指向同一提交。随后执行完整构建、宿主烟雾测试、真实模块包兼容测试、标准包启动和更新器沙箱测试，再通过统一发布脚本推送标签、创建不可变 Release 并验证远端大小与 SHA-256；版本索引/模块目录最后单独提交，验证公开内容后才运行保留清理。发布脚本统一解析显式、环境变量和 Windows 系统代理，显示大文件上传进度，对无进度上传执行有限重试；只有同名未完成资产可以自动清理，已上传资产永不覆盖。

标准 GitHub Release 只包含主程序 ZIP。带模块的完整离线包是本地交付物，不上传到 GitHub Release。

每个替换项先备份并写入原子恢复记录，再替换目标。失败恢复采用复制，所有文件成功恢复前不消耗备份；二次失败保留 `.update-transaction-*/recovery.json` 与旧文件，并在 `data/updates/recovery-required.json` 标记。该标记禁止新更新/回退及清理恢复资产，也禁止重启混合版本。更新器支持手动 `--recover`，恢复前整份记录校验应用身份、路径边界、用户 data 保护及链接路径；成功后才清除标记和事务目录。

从 0.4.7 起，空 Applying 事务与恢复标记早于首次替换，pending 移入事务不再触发重复自动安装。所有文件替换完成后刷盘记录 Committed，已提交事务只能收尾、不能恢复旧文件。启动在加载正常窗口前检查标记及顶层未完成事务。更新/回退使用当前安装的更新器独立副本，不执行目标旧包中的更新器；旧版本自身不能被追溯改写，但独立副本和保留备份可用于手动恢复。

准备重启与更新器执行替换前共用兼容验证器，重新读取 installed.json 和包内清单。模块登记变更、包清理和应用替换共享有界跨进程门禁；替换过程中不会发生本程序发起的模块登记变化。待安装记录携带目标 API 范围与 Schema 上限；新 ZIP 的 release-compatibility.json 允许旧宿主 pending 在 SHA-256 验证后取得相同信息，无信息、身份不一致或损坏记录拒绝安装。内部记录变化不提升 SDK/API 或服务器 Schema。详见[稳定性设计与检查](STABILITY_OPERATIONS_STORAGE_AND_RECOVERY_DESIGN.md)。
