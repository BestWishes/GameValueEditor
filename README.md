## 优先说明

1、开源，有清晰的扩展规范，用户可以使用AI进行非常方便的模块化扩展，扩展后再上传到项目，实现循环互惠。

2、免费，永久无限制使用所有功能。

3、干净，无任何多余逻辑，无任何广告、弹窗、收集之类的让人不爽的逻辑。

4、实用：

- 多游戏同时运行，一个编辑器即可修改。
- 多进程游戏，不需要用户区分哪一个才是数据进程，自动识别自动处理。
- 支持类似CE功能的加速、扫描。
- 便捷，将目标保存到字段，重启游戏后仍可自动找到，不依赖上一次运行的临时地址。
- 模块化，可以只下载自己玩的游戏的编辑模块，用不到的不用下载。
- 版本化，可同时支持同一个游戏的不同版本。
- 也可以下载完整离线包，包含全部模块，解压即玩。

一个面向 Windows 离线单机游戏的本地数值扫描与管理工具。它不仅保存临时地址，还把玩家确认过的字段整理到按游戏、按版本隔离的本地游戏库中。

> 最新稳定版本：`v0.2.0`。当前源码正在开发 `v0.3.0-preview.12`。

## 主要功能

- 连接本机正在运行的 Windows 进程；Electron/NW.js、Unity 等多进程游戏可任选同一游戏实例中的一个进程，应用会自动归组并把扫描与专属修改转到实际数据进程。
- 精确扫描 `4 Bytes`、`8 Bytes`、`Float` 和 `Double`。
- 数值类型可选择“所有类型”，一次检查全部基础数值表示。
- 可选择“直接数值”“按比例存储”或“所有套路”；比例参数不会被拆成大量重复套路。
- 按“精确值、已改变、未改变、增加、减少”继续过滤。
- 首次扫描会完整保留所有候选，不会因结果过多而提前截断；大量候选使用程序目录下的临时扫描文件继续过滤，界面列表最多显示前 1,000 条并始终显示后台候选总数。
- 支持撤销上一次过滤；候选少于 100 个时实时刷新当前值，并保留“首次”和“上一次”数值。
- 扫描结果支持 `Ctrl`、`Shift` 和 `Ctrl+A` 标准多选，可把所选地址批量修改为同一个界面值；保存字段仍要求单选。
- 双击候选地址即可先试改，不需要先保存字段。
- 玩家在保存字段时手动填写备注名称；程序不会猜测字段含义。
- 左侧游戏库支持搜索、清空搜索、置顶、锁定、重命名、连接、断开连接和从库移出；搜索无结果不会清空右侧正在使用的游戏。顶部“连接”连接进程下拉框当前选择的进程，编辑区“连接/断开”只操作右侧当前游戏库条目，两组操作不会串用选择目标。若条目已安装专属模块，“从库移出”会同时卸载模块；已连接进程仍保留为可继续通用扫描的临时会话。
- 游戏库保存各游戏的 Windows 图标，以 `✓` / `✕` 标识连接状态，以拼图标志标识本地专属模块，并可按连接状态、名称或本地模块排序；可同时连接多个游戏并在左侧切换各自的扫描、加速和锁定会话。游戏主进程退出或 PID 被复用时会在约一秒内自动断开并同步状态；多进程游戏的数据进程单独重建时会自动重新定位，并清空已经失效的临时扫描结果。
- 置顶或锁定的游戏条目不能删除；锁定不影响扫描、修改数值、保存字段或其他正常功能。
- 根据产品版本、文件版本、架构以及 EXE/关键运行时文件的组合指纹保存独立版本档案；下拉框用“当前运行版本/历史版本 + 日期 + 字段数”帮助选择，技术版本和指纹保留在详情中。
- 当前构建变化时不会套用旧的原始内存地址；构建仍受支持的游戏专属字段会按语义键迁移到新版本档案。
- 静态地址优先保存为“模块 + 偏移”；动态地址保存为本次进程会话地址，并在重启后要求重新定位。
- 所有档案只保存在本机，写入时自动保留上一份配置备份。
- 支持浅色、深色、护眼墨绿、暖砂纸张和雾蓝灰五套完整主题；标签页、列表、输入弹框、确认弹框、错误弹框和标题栏均跟随当前主题，并在进程列表显示程序图标。
- “本游专属”支持从独立的 [GameValueEditor-Modules](https://github.com/BestWishes/GameValueEditor-Modules) 模块中心检查、校验、按需安装和卸载游戏专属模块；未入库但已连接的游戏也能“检查新有”，安装成功后会自动生成正常游戏库条目。一个游戏包可以包含多个竖向排列的游戏内编辑模块。
- 模块顶部可查看整个游戏专属模块的贡献者；GitHub 名称可打开个人主页，并可按名称、首次贡献日期或最新贡献日期排序。贡献者不按具体编辑功能分级，也不显示贡献次数或排名。
- “快捷入口”支持直接编辑备注名称、分组和当前值，并可锁定目标值持续保持。
- 分组输入框支持直接输入、按文字筛选已有分组，或保留新文字创建分组。
- 官方 `fzzml` 可选模块包含“背包物品”和“人物属性”：背包支持筛选、多选和持久化修改；人物属性按人物列出五维并实时修改，但仅本次游戏运行有效，关闭游戏后失效，也不会在重启后自动重应用。官方 `WorldApart` 模块提供可持久化的背包与人物属性编辑，并支持按人物属性名称筛选。
- 顶部倍速栏支持把当前连接的 x64 单机游戏设置为 `0.01`–`100.00` 倍，最多两位小数；小于 1 可减速，大于 1 可加速，应用新倍数和回正时保持游戏时钟连续。倍速按钮在每次操作后共同冷却至少 2 秒，无法识别计时入口时会安全失败。
- 右下角可检查 GitHub 正式版更新，更新操作不再使用括号包围；“检查更新”保留十秒防连点，但发现新版本后“更新”按钮立即可用。更新包校验后由用户决定立即重启安装，或留到下次启动自动安装。
- 右下角“官网”按钮可打开本项目 GitHub 主页，并带有两秒防重复点击冷却。

## 下载与运行

在 GitHub Releases 下载稳定版压缩包，或使用源码生成的预览版压缩包，解压后运行：

```text
GameValueEditor.exe
```

发布包为 Windows x64 自包含版本，不要求用户另行安装 .NET。某些高权限游戏需要以管理员身份运行本工具才能访问。

## 基本使用

1. 启动离线单机游戏。
2. 在顶部选择游戏进程并点击“连接”。
3. 输入游戏当前显示的数值，选择数值类型和搜索套路，点击“首次扫描”。
4. 回到游戏改变数值。
5. 在工具中选择“精确值、增加了、减少了”等条件，点击“再次扫描”。
6. 确认正确地址后，先点击“保存入库”。
7. 选中扫描结果，点击“保存选中字段”。
8. 玩家手动输入名称，例如“洞府残核”；名称不由程序自动推导。

## 游戏版本规则

同一个游戏可以保存多个版本档案。普通游戏使用 EXE 的 SHA-256；Unity IL2CPP 游戏还会组合 `GameAssembly.dll` 与 `global-metadata.dat` 的 SHA-256。这样即使启动 EXE 和显示版本号都没变，运行时代码变化也不会被误认为旧构建。

```text
游戏
├─ 版本 A（组合构建指纹 A）
│  ├─ 玩家命名字段 1
│  └─ 玩家命名字段 2
└─ 版本 B（组合构建指纹 B）
   └─ 玩家命名字段 1
```

## 数据位置

应用采用便携式数据目录。本地游戏库保存在程序所在文件夹的：

```text
data\library.json
```

备份文件：

```text
data\library.backup.json
```

崩溃日志（如有）：

```text
data\crash.log
```

游戏图标、可选模块和待安装更新分别保存在 `data\icons`、`data\modules` 和 `data\updates`。应用更新不会覆盖整个 `data` 目录。

## 从源码构建

要求：Windows 10/11 和 .NET 8 SDK 或更高版本。

```powershell
dotnet build GameValueEditor.sln -c Release
dotnet run --project tests/GameValueEditor.SmokeTests/GameValueEditor.SmokeTests.csproj -c Release
```

生成自包含发布包：

```powershell
./scripts/publish.ps1
```

输出位于 `dist/`。

验证最终 ZIP 中的程序能够正常启动：

```powershell
./scripts/test-package-startup.ps1 -ArchivePath ./dist/GameValueEditor-v0.3.0-preview.12-win-x64.zip
```

官方游戏模块已迁移到独立仓库。在相邻目录克隆模块中心后，可在那里构建 `fzzml` 模块：

```powershell
cd ../GameValueEditor-Modules
./scripts/publish-fzzml.ps1 -Version 2.0.0
```

在尚未发布 GitHub 模块资产时，可创建一个仅供本机验证、已经预装 fzzml 模块的预览包：

```powershell
./scripts/create-local-fzzml-preview.ps1
```

## 搜索套路与专属适配器

通用搜索套路保存“如何编码界面数值”，例如直接存储或按可配置倍数存储。玩家确认并保存字段后，应用会把套路和参数保存到对应游戏版本。

如果游戏的真实数值只能通过其运行时对象和自身保存函数修改，则使用按构建指纹严格匹配的可选游戏模块。游戏专属模块代表整个游戏，下面可以注册“背包物品”“人物属性”等多个游戏内编辑模块。官方 `fzzml` 背包编辑器按物品名实时定位记录并调用游戏自身保存流程；应用不会把超过 9999 的值主动拆成多个堆叠。人物属性编辑器修改本次进程中的运行时配置并触发游戏聚合与界面通知，不写存档、不锁定，也不在重启后自动重应用。官方 `WorldApart` 模块每次从当前存档重新定位背包与人物属性，在 Unity 主线程调用游戏自身自动存档并回读，因此重启游戏或编辑器后仍能按语义键继续使用。

扩展新游戏前请阅读 [新游戏搜索套路与专属适配器扩展指南](docs/GAME_EXTENSION_GUIDE.md) 与 [游戏专属模块和游戏内编辑模块设计](docs/GAME_MODULE_AND_EDITOR_MODULE_DESIGN.md)。

## 当前限制

- 当前版本仅支持 Windows x64 主程序。
- 不提供驱动、反反作弊、隐藏进程或绕过保护功能。
- 通用扫描得到的动态堆地址在游戏重启后通常需要重新扫描；只有已实现且构建指纹匹配的专属适配器能自动重新定位。
- 不支持服务器权威的在线游戏数值。
- 游戏加速依赖目标进程导入的常见 Windows 计时 API；部分自定义计时器或受保护程序可能不支持。
- 修改异常数值可能损坏游戏进度，建议先备份存档。
