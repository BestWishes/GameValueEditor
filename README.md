# 肝肾大圣-单机游戏数值编辑器

## 优先说明

1：全功能永久无限制使用。

2：本项目长期开源维护，可由用户提交更新。

3：新出游戏或者新增游戏编辑功能，可以联系作者QQ群：1127372613。

4：旨在做一款适用于大多数单机游戏的数值编辑器，最终目标是维护用户的肝和肾，以便用户有富余的肝力、肾力用于美好的日常生活当中。

一个面向 Windows 离线单机游戏的本地数值扫描与管理工具。它不仅保存临时地址，还把玩家确认过的字段整理到按游戏、按版本隔离的本地游戏库中。

> 最新稳定版本：`v0.2.0`。当前源码正在开发 `v0.3.0-preview.5`。

## 主要功能

- 连接本机正在运行的 Windows 进程。
- 精确扫描 `4 Bytes`、`8 Bytes`、`Float` 和 `Double`。
- 数值类型可选择“所有类型”，一次检查全部基础数值表示。
- 可选择“直接数值”“按比例存储”或“所有套路”；比例参数不会被拆成大量重复套路。
- 按“精确值、已改变、未改变、增加、减少”继续过滤。
- 支持撤销上一次过滤；候选少于 100 个时实时刷新当前值，并保留“首次”和“上一次”数值。
- 扫描结果支持 `Ctrl`、`Shift` 和 `Ctrl+A` 标准多选，可把所选地址批量修改为同一个界面值；保存字段仍要求单选。
- 双击候选地址即可先试改，不需要先保存字段。
- 玩家在保存字段时手动填写备注名称；程序不会猜测字段含义。
- 左侧游戏库支持搜索、清空搜索、置顶、锁定、重命名、连接、断开连接和从库移出；搜索无结果不会清空右侧正在使用的游戏。已连接条目从库移出后仅删除入库记录，当前进程仍保持连接。
- 游戏库保存各游戏的 Windows 图标，以 `✓` / `✕` 标识连接状态，并把正在连接的游戏排在最前；可同时连接多个游戏并在左侧切换各自的扫描、加速和锁定会话。游戏进程退出或 PID 被复用时会在约一秒内自动断开并同步状态。
- 置顶或锁定的游戏条目不能删除；锁定不影响扫描、修改数值、保存字段或其他正常功能。
- 根据产品版本、文件版本、架构以及 EXE/关键运行时文件的组合指纹保存独立版本档案；下拉框用“当前运行版本/历史版本 + 日期 + 字段数”帮助选择，技术版本和指纹保留在详情中。
- 当前构建变化时不会套用旧的原始内存地址；构建仍受支持的游戏专属字段会按语义键迁移到新版本档案。
- 静态地址优先保存为“模块 + 偏移”；动态地址保存为本次进程会话地址，并在重启后要求重新定位。
- 所有档案只保存在本机，写入时自动保留上一份配置备份。
- 支持完整协调的浅色、深色主题（包括标签页、列表、弹窗和标题栏），并在进程列表显示程序图标。
- “本游专属”支持从 GitHub 检查、校验并按需安装游戏专属模块；只装配游戏身份和构建指纹都匹配的模块。
- “快捷入口”支持直接编辑备注名称、分组和当前值，并可锁定目标值持续保持。
- 分组输入框支持直接输入、按文字筛选已有分组，或保留新文字创建分组。
- 官方 `fzzml` 可选模块可读取、按名称或数量筛选并直接修改背包物品，支持标准多选批量修改物品总数。
- 顶部倍速栏支持把当前连接的 x64 单机游戏设置为 `0.01`–`100.00` 倍，最多两位小数；小于 1 可减速，大于 1 可加速，应用新倍数和回正时保持游戏时钟连续。倍速按钮在每次操作后共同冷却至少 2 秒，无法识别计时入口时会安全失败。
- 右下角可检查 GitHub 正式版更新；“检查更新”保留十秒防连点，但发现新版本后“更新”按钮立即可用。更新包校验后由用户决定立即重启安装，或留到下次启动自动安装。
- 右下角“官网”按钮可打开本项目 GitHub 主页，并带有两秒防重复点击冷却。

## 下载与运行

在 GitHub Releases 下载稳定版压缩包，或使用源码生成的预览版压缩包，解压后运行：

```text
GameValueEditor.exe
```

发布包为 Windows x64 自包含版本，不要求用户另行安装 .NET。某些高权限游戏需要以管理员身份运行本工具才能访问。

## 基本使用

1. 启动离线单机游戏。
2. 在顶部选择游戏进程并点击“连接”。
3. 输入游戏当前显示的数值，选择数值类型和搜索套路，点击“首次扫描”。
4. 回到游戏改变数值。
5. 在工具中选择“精确值、增加了、减少了”等条件，点击“再次扫描”。
6. 确认正确地址后，先点击“保存入库”。
7. 选中扫描结果，点击“保存选中字段”。
8. 玩家手动输入名称，例如“洞府残核”；名称不由程序自动推导。

## 游戏版本规则

同一个游戏可以保存多个版本档案。普通游戏使用 EXE 的 SHA-256；Unity IL2CPP 游戏还会组合 `GameAssembly.dll` 与 `global-metadata.dat` 的 SHA-256。这样即使启动 EXE 和显示版本号都没变，运行时代码变化也不会被误认为旧构建。

```text
游戏
├─ 版本 A（组合构建指纹 A）
│  ├─ 玩家命名字段 1
│  └─ 玩家命名字段 2
└─ 版本 B（组合构建指纹 B）
   └─ 玩家命名字段 1
```

## 数据位置

应用采用便携式数据目录。本地游戏库保存在程序所在文件夹的：

```text
data\library.json
```

备份文件：

```text
data\library.backup.json
```

崩溃日志（如有）：

```text
data\crash.log
```

游戏图标、可选模块和待安装更新分别保存在 `data\icons`、`data\modules` 和 `data\updates`。应用更新不会覆盖整个 `data` 目录。

## 从源码构建

要求：Windows 10/11 和 .NET 8 SDK 或更高版本。

```powershell
dotnet build GameValueEditor.sln -c Release
dotnet run --project tests/GameValueEditor.SmokeTests/GameValueEditor.SmokeTests.csproj -c Release
```

生成自包含发布包：

```powershell
./scripts/publish.ps1
```

输出位于 `dist/`。

验证最终 ZIP 中的程序能够正常启动：

```powershell
./scripts/test-package-startup.ps1 -ArchivePath ./dist/GameValueEditor-v0.3.0-preview.5-win-x64.zip
```

构建官方 fzzml 可选模块并更新 `modules/catalog.json` 中的 SHA-256：

```powershell
./scripts/publish-module.ps1 -Version 1.0.0
```

在尚未发布 GitHub 模块资产时，可创建一个仅供本机验证、已经预装 fzzml 模块的预览包：

```powershell
./scripts/create-local-fzzml-preview.ps1
```

## 搜索套路与专属适配器

通用搜索套路保存“如何编码界面数值”，例如直接存储或按可配置倍数存储。玩家确认并保存字段后，应用会把套路和参数保存到对应游戏版本。

如果游戏的真实数值只能通过其运行时对象和自身保存函数修改，则使用按构建指纹严格匹配的可选游戏模块。官方 `fzzml` 模块按物品名实时定位背包记录，直接写入物品总数并调用游戏自身的缓存、界面整理和保存流程；应用不会把超过 9999 的值主动拆成多个堆叠。自动化实机测试仍把测试写入限制在 1000 以内，以免打扰玩家存档。

扩展新游戏前请阅读 [新游戏搜索套路与专属适配器扩展指南](docs/GAME_EXTENSION_GUIDE.md)。

## 当前限制

- 当前版本仅支持 Windows x64 主程序。
- 不提供驱动、反反作弊、隐藏进程或绕过保护功能。
- 通用扫描得到的动态堆地址在游戏重启后通常需要重新扫描；只有已实现且构建指纹匹配的专属适配器能自动重新定位。
- 不支持服务器权威的在线游戏数值。
- 游戏加速依赖目标进程导入的常见 Windows 计时 API；部分自定义计时器或受保护程序可能不支持。
- 修改异常数值可能损坏游戏进度，建议先备份存档。

## 使用范围

本项目仅面向离线单机游戏、个人研究、调试和可访问性用途。请遵守游戏许可协议和当地法律，不要用于多人在线游戏、破坏公平性或规避安全机制。
